# MBTI for Agent：用稳定偏好推动游戏交锋

状态：核心方案，待实现和验证。2026-09-22。

目标是让不同稳定人格的 AI 在游戏里形成不同的判断、行动和互动，带来更多样的对局。用户只需指定 MBTI 或选择随机分配。实现仅依赖现有模型 API、提示词和游戏上下文，不做微调、偏好训练，不增加人格卡、候选打分、程序抽样或额外温度设计。

## 1. 把 MBTI 写成决策习惯

每种 MBTI 对应一组稳定的软偏好，由四个维度组合生成。代码在每次请求中保留这些偏好，并按当前可见局势补充少量相关提示，用于发言、夜间行动、投票等请求。稳定的是习惯，不是固定反应；同一种性格也可以坚持、妥协、试探或沉默，取决于当前行动机会与局势。

| 维度 | 写进提示词的行为偏好 | 狼人杀中的表现 |
| --- | --- | --- |
| E / I | E 倾向通过主动询问和提议获取反馈；I 倾向先整合已有信息，再聚焦回应 | 主动发起狼队分工，或先核对信息再提出关键异议 |
| S / N | S 优先具体发言、投票和行动记录；N 倾向比较动机、关系与整体解释 | 抓前后改口，或检查可能的阵营配合 |
| T / F | T 倾向比较逻辑一致性与行动代价；F 倾向考虑各方立场、信任影响和说服方式 | 直接质疑矛盾，或争取摇摆玩家、协调队友 |
| J / P | J 倾向形成计划并持续推进；P 倾向保留备选、根据新信息调整 | 继续已约定分工，或提出改线方案 |

这些是游戏预设的设计假设，需要用实际对局验证。不能把某个类型等同于聪明、诚实或激进，也不能规定某类型一定悍跳。所有类型都能使用合法战术；明确事实、身份目标与规则优先。

例如 ENTP 的行为提示可以写成：

```text
你倾向主动提出计划，并通过点名询问或试探获得反馈。
面对不完整信息，你会考虑几种阵营解释，但必须区分猜测和事实。
比较行动时，你重视逻辑是否成立、行动能带来什么收益与代价。
你愿意根据新信息或队友回应修改计划；没有新依据时不要随意改口。
把这些偏好落实在本次行动和互动方式中，不要在发言中解释 MBTI。
游戏规则、你的身份目标和明确证据优先于这些偏好。
```

它没有规定具体台词或固定战术。模型仍根据当前局势决定做什么，MBTI 影响它习惯从哪里入手、怎样取舍和回应别人。

## 2. 代码按情境组织提示，同时影响行为和语言

代码负责把稳定偏好与当前情境联系起来。先从行动请求和本人可见事件识别明确情境，例如轮到发言、队友提出方案、收到新查验；对“被质疑”等需要理解语义的情境，仅在有可靠标记时补充提示，否则直接交给模型理解原始发言，不额外调用一个模型做分类。

```ts
const cues = buildBehaviorCues({
  mbti: player.mbti,
  request,
  visibleEvents,
  personalMemory,
});
// 返回相关的行为与表达提示，不返回目标、战术或替玩家选好的答案。
```

每轮只补零到两条相关提示，不要求四个维度逐项表演。比如队友提出不同方案时，可以提醒偏 J 的玩家“结合原计划的依据回应，条件已变化时可以调整”，提醒偏 P 的玩家“可以比较新的提议，也要考虑已经作出的约定”。它们不要求一定坚持或一定改线，遇到明确证据都可以作出相同选择。

语言风格也通过软偏好影响：更倾向直接点名交锋，或集中解释关键一点；更常引用具体事件，或提出一种关系假设；更习惯直接指出矛盾，或先接住对方顾虑。这些表现可以交叉出现，不规定 E 必须反问、I 必须短句、F 必须温柔，也不设置固定口头禅和句式。

需要辅助时可加入一条简短口语示例，供理解节奏，不作为每轮必带的台词模板。发言长度随信息量和游戏时限变化，允许停顿、改口、情绪和不同表达；避免每次都输出完整分析报告。具体行动由局势决定，语言服务于本次行动。

这仍是通过 API 输入进行软影响：代码让相关提示在合适时刻出现，并保持上下文连续，不能直接控制模型内部推理，也不能保证它每次都遵循。

## 3. 保持跨轮连续性

开局确定 MBTI 后，本局保持不变。每次 API 请求显式携带同一组基础偏好，再加入适用的情境提示，不能只在开局说一次，也不能指望 API 自己记住人格。

每次请求包含：

```text
游戏规则与当前行动要求
+ 稳定的 MBTI 偏好与少量当前情境提示（行为、表达）
+ 现有游戏攻略
+ 该玩家能看到的事件
+ 该玩家此前的判断和计划
→ API 返回本次行动、发言及简短状态更新
→ 规则校验并记录实际接受的结果
→ 下一次请求继续使用
```

每个行动正常情况下只调用一次模型，不增加人格评审或多轮重写。格式错误、非法行动和超时沿用游戏现有处理。

个人上下文只保留必要的连续性：自己当前相信什么、已经公开说了什么、与队友确认了什么、接下来准备做什么。公开说法与真实判断分开，避免狼人把自己编造的查验当成事实；自己的提议也不能被记成队友已经同意。

只保存有效的状态更新，未接受或过期的行动不能被记成已经执行。各 AI 仅读取自己的授权信息，MBTI 不改变身份和信息权限。

这样，稳定的是处理事情的偏好，判断和战术仍可以随着事件变化。遇到强反证改口不算人格不稳定，忘记前文后无理由反复才是需要检查的问题。

## 4. 让人格通过互动表现出来

游戏流程要让后一位真正读到前一位的发言和行动。狼人夜聊中，队友可以同意、反对或修改提议；在规则允许的回应机会内，原提议者再作出选择。讨论仍受轮数和时间限制，不因人格无限延长。

例如 A 提出自己悍跳，B 认为先观察更合适。A 可以坚持并争取配合，也可以接受 B 的理由调整方案。这些选择由双方各自的预设和局势共同影响，不预先安排冲突或强制他们达成共识。现有规则若没有再次回应的机会，需要单独调整讨论流程，不能期待 prompt 自动创造发言权限。

对局变化来自开局的人格组合、身份与座位，以及玩家之间持续产生的新信息。人格与身份独立分配，首夜不能凭性格或名字判断谁是预言家。固定人格也不承诺每次运行都会得到不同结果，我们关注的是实际对局是否更丰富，而不是人为制造随机动作。

以后接入德州、斗地主时沿用同一套 MBTI 偏好，替换游戏规则、攻略和可见局面即可开始测试；不保证每个维度在每类游戏里都有同样明显的效果。

## 5. 怎样确认影响到了行为

先做简单对照：固定同一模型、身份和可见局面，比较无 MBTI、只有稳定偏好、稳定偏好加情境提示，并替换不同 MBTI 多次观察实际行动，再开完整对局比较不同人格组合。

重点看三件事：

- 同一预设跨轮次是否保持可辨认的习惯，例如怎样提议、取证和改线。
- 不同预设是否改变行动和互动，例如主动提出分工、回应异议、调整计划及实际投票，而不只是换措辞。
- 多样性是否来自有依据的交锋，而不是遗忘、非法行动或毫无理由的反复。

同时检查语言是否自然、有差异且不过度重复：若同一种类型每轮都反问、复用示例或执行同一套路，就减少提示的强制性。人格稳定不以“每次反应一样”衡量。

运行记录保存本次使用的预设、附加的情境提示、当时可见信息、行动、简短决策摘要和实际结果。摘要是模型自述，不能单凭它声称 MBTI 已生效；需要结合实际行为对照。真人局其他玩家的私有记录在对局结束后查看。

API 提示属于软约束，无法保证每次严格遵循。若只有语言变化，没有行动差异，就调整具体行为提示并重新测试，不宣称已经实现稳定人格。

## 6. 实施顺序

1. 做 MBTI 指定和随机预设，开局保存，局内固定。
2. 在每个决策请求中加入稳定偏好，由代码按明确情境补充少量行为与表达提示，保持个人判断与计划的连续性。
3. 检查夜聊和白天发言是否真正接收前序回应，在现有时间限制下验证交锋效果。
4. 通过运行记录和对照局调整提示，确认行为差异、语言自然度与响应速度，减少机械重复。

本文更新的是方案，现有本地 MBTI 改动尚不能视为上述机制已完成或已验证。
