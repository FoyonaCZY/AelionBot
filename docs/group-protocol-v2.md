# 群聊通信协议 V2

本次实现将群成员视为独立参与者：公开消息平等送达，每个 Bot 在自己的群工作区判断是否发言、认领任务、补充或反驳。私聊历史与群上下文保持隔离。没有主持人或发言裁判。

## 上下文与渐进式披露

| 数据 | 所属范围 | 如何进入模型上下文 |
| --- | --- | --- |
| 人与 Bot 的私聊 | 原有 Bot 私聊 | 沿用原有历史与压缩 |
| Bot 间私聊 | 原有私聊线程 | 沿用原有机制 |
| 群公共记录 | 一个群 | 当前收件批次、首次少量公开消息；更早内容按需读取 |
| Bot 的群工作记录 | Bot × 群；设计任务另有任务范围 | 自己的工具结果、工作记录和已读消息，独立压缩 |
| 群任务表 | 一个群 | 少量任务摘要；完整清单按需读取 |
| 自己的历史经验 | 当前 Bot | `history_search` 找来源，再用 `history_read` 读取；不自动复制私聊原文 |

新群工作区默认只装载最近 4 条公开消息，当前收件批次另行提供。单条自动装载的群消息最多 1800 字符，明确标注截断和回读位置。`group_read` 支持历史翻页，以及指定 `messageId`、`offset` 精读长消息。

历史搜索始终以当前 Bot 的身份执行。回查得到的私有原文留在这个 Bot 的群工作区；只有 Bot 明确选择发布的内容才成为群记录。既有个人记忆算法保持不变。

旧群上下文首次迁移时写入 `group-context-backups/`。保留真实工具交换，丢弃混入的未发布草稿，重建少量公共消息。V2 使用独立的群压缩范围，不重置私聊。后续继续使用现有按容量压缩机制，原始公共记录可回查。

## 收件箱

1. 一次公开发言生成一条群消息和各接收人的独立 delivery。
2. 所有现有成员收到同一消息；`@` 只提示关注，不筛选接收人。
3. Bot 忙时消息保留 queued；空闲 Bot 并发开始处理。
4. 一个 Bot 一次处理一批消息。执行中到来的消息，在下次模型调用前读取，即上一批工具结果已经保存的边界。不同设计任务的输入仍分别处理。
5. 普通新消息不取消推理或工具，不因群最新序号变化而丢弃慢成员的答复。
6. 显式停止和成员移除仍取消执行。私聊输入保留现有优先级，被让出的群收件批次重新排队，已执行结果保留。

delivery 的“已处理”与“已回复”不同。Bot 可以看完后选择静默，不必为每条消息发言。

## 发件箱

`group_send_message` 用于明确发表进展、问题、提醒、反对意见或结果，可选择附件、消息类型和稳定的 `clientMessageId`。工具调用前后的普通模型文字不自动群发。最终答复也经过相同发件箱。

发件流程：

```text
选定公开内容 → 持久化 pending 发件
             → 同一次保存提交消息、各接收人 delivery、sent 回执
             → 通知界面与接收人
```

提交失败会回滚内存中的公开消息和投递记录，保留 pending。重试同一个发件标识不会重复投递；同一标识不能改成不同内容。`group_outbox` 只读取当前 Bot 的发件回执。应用重启不会自动发送尚未提交的草稿。

传输层不做跨成员语义去重，不压制相似意见或较慢的反驳。对于同一成员在同一任务来源下完全相同的最终答复，保留幂等保护。正常交流中的克制由提示词引导，没有新增发言评分算法。

## 群任务

群任务表保存明确的工作范围、原始用户消息、负责人、状态、公开摘要和修订号。执行细节留在自己的工作上下文。界面可展开查看当前任务和阻碍。

- `group_tasks`：按需查看分工。
- `group_task_claim`：以已有 taskId 续接，或以稳定 key 创建并认领任务。认领在同一个 Store 写入者中同步完成，同一任务只有一个负责人。未认领成功时不重复执行。
- `group_task_update`：使用当前 revision 更新进度，冲突时返回最新记录；可完成、报告阻碍或释放任务。

任务状态：`open → working → completed / blocked`；释放回到 `open`，中断进入 `paused`。成员离开后释放未完成任务，保留核对已有结果的提醒。不同 key 的语义重叠不由底层自动判定，Bot 应先看任务表。

认领不会新增授权。新任务必须引用真实的用户任务或已核验的任务来源，成员加入通知不能成为操作授权。其他成员无需认领也可以提出意见。

已认领且仍 working 的任务不能靠一句“稍后处理”结束运行。执行循环继续推进，直到完成、记录阻碍或释放；连续三次提前答复，或连续三轮工具调用只重复相同成功操作和结果时，系统会如实标记受阻并保留检查点，不伪称完成。真实工具失败、停止、私聊抢占和应用重启分别进入失败可重试、取消、暂停和中断状态。公共任务摘要每次模型调用重新提供，不依赖压缩摘要猜测状态。任务成果与值得保留的过程说明使用现有文件工具写入文档，公开汇报必要的结果和位置。

## 私聊兼容边界

共享运行时代码中，新增收件、任务约束与群上下文逻辑仅在 `groupOrigin` 下启用。私聊历史、私聊队列、Bot 间私聊与记忆写入算法没有更换。私聊工具不提供群列表预览或群历史读取，避免公开群内容被主动带入私聊上下文；群内仍可按需检索 Bot 自己的私有历史。

私聊输入抢占群工作时，禁止继承群运行的 `supersedesRunId`，避免把群计划或设计会话绑定到私聊。群工作在 Bot 界面的既有来源卡片仍可显示，但它不表示群消息已写入私聊模型历史。

General 与 Designer 共用群 gateway、收发及任务契约，执行工具和设计文件权限保持各自限制。

## 本次未改变的范围

- 长期记忆的提取、排序、遗忘算法。
- 定时遗忘、定时上下文清理策略；本次继续按容量压缩。
- 发言价值评分、语义冲突判定或 Bot 之间的领导层级。
- 崩溃后自动重放外部操作。工作记录保留，中断操作需核对后继续。
