# AelionBot v0.41.0

这一版可以给同一个 Bot 开多个工作会话，把不同的事情分开做，几件事也能同时进行。

## 简体中文

### 工作会话

- 从左上角“+”菜单、Bot 的右键菜单或聊天顶部的文件夹按钮新建工作会话。会话和私聊用起来一样，有步骤过程、流式回复和工作动画；聊天记录和上下文各自独立，长期记忆仍然共享。
- 每个会话可以设置自己的工作目录和本机权限，计划和目标也只属于这个会话。
- 同一个 Bot 的不同会话可以同时工作。在某个会话里发消息，只会打断这个会话正在做的事；停止按钮也只停当前会话。群聊和协作任务跟私聊主聊天走同一条线，不会挡住工作会话。
- Bot 的图形桌面同一时间只给一个会话用，别的会话需要时会先做其他部分或稍后再操作。工作电脑（Linux）里同一个 Bot 的各个会话共用一个工作目录，同时改同一个文件会互相覆盖；本机文件夹可以每个会话分开设置。
- 在会话里建的定时任务会在这个会话里执行，右侧面板只显示当前会话的任务。删除会话会一起删掉它的定时任务。
- 侧边栏里，会话列在所属 Bot 下面，每个一行；点 Bot 行右下角的按钮可以折叠。右键会话可以改名、换目录、归档或删除。
- Bot 查找历史记录时，当前会话里的内容排在前面。

### 群聊里的工作电脑卡片

- 在群聊里，右侧的工作电脑卡片显示最近在操作桌面的那位成员的桌面，并标出是谁的。全屏查看时不会因为别的成员开始操作而切走。

## English

### Work sessions

- Start a work session from the “+” menu, a Bot's context menu or the folder button in the chat header. A session works like the private chat, with its steps, streamed replies and working status, but keeps its own history and context; long-term memory stays shared.
- Each session can have its own folder and local permission mode, and its plans and goals stay in that session.
- A Bot works in its sessions at the same time. A message interrupts only the work in the chat it is sent in, and Stop stops only that chat. Group and delegated work run alongside the private chat and never hold up a session.
- One session at a time drives the Bot's desktop; another that needs it does other work first or tries again later. On the Linux work computer a Bot's sessions share one working folder, so editing the same file from two sessions at once overwrites; local folders can differ per session.
- A task scheduled in a session runs in that session, and the task panel shows the open chat's tasks only. Deleting a session deletes its tasks.
- Sessions are listed under their Bot in the sidebar, one line each, and fold from the button on the Bot's row. Right-click a session to rename it, change its folder, archive or delete it.
- When a Bot searches its history, the current session's records come first.

### Work computer card in groups

- In a group, the work computer card shows the desktop of the member that last worked on it, labelled with that member. Full screen stays on the desktop it opened with when another member starts working.
