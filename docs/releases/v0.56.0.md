# AelionBot v0.56.0

## 简体中文

### 保险库（Vault）

- 设置页新增“保险库”，通过系统加密存储（macOS Keychain / Windows DPAPI）安全保存登录凭据、个人联系与地址、支付卡、SSH 密钥、API Key 与自定义机密，并支持基于 TOTP 密钥实时生成动态验证码；绝不以明文落盘。
- 保险库默认供所有 Bot 共享（也可按条目限定可用 Bot），但模型全程看不到明文，只看到条目标题、字段名与掩码预览。Bot 通过占位符调用时，由主进程在执行边界按需解密并盲注到工作电脑桌面、本机桌面、终端（环境变量与用完即毁的临时只读 SSH 密钥文件，含私钥口令自动接管）、Python 环境变量或 MCP 调用，同时对工具输出、控件文本、日志、长期记忆与诊断导出做全链路脱敏。
- 支持两种存入方式：Bot 需要密码、银行卡或私钥时可在对话中弹出安全录入卡（桌面端与已配对手机 PWA 均支持），内容直接加密存入保险库、不进入聊天记录；在对话中直接让 Bot 保存信息时，存入后会自动洗脱对话历史与工具参数中的明文。
- 提供按条目的分级人类审批策略（自动、匹配绑定时自动、本任务询问一次、每次询问），支持绑定域名、应用与 MCP 服务并在目标不匹配时告警；支付卡仅限桌面输入通道且强制人工确认，所有操作均记录使用审计。跨机整机备份（`.aelionbackup`）经口令封包迁移保险库，单个 Bot 导出（`.aelionbot`）绝不包含保险库数据。

### IM 连接器流式输出

- IM 会话中的任务进度说明和最终回复现在会实时推送，不再等到整轮任务完成才一次发回；流式输出中未闭合的图表与交互小组件围栏会自动隐藏，完成后以可读文本呈现。
- 各平台按原生能力实现流式更新并自动降级：飞书使用 CardKit 流式卡片（扫码创建与手动配置已加入 `cardkit:card:write` 权限，未开通时自动降级为原地更新卡片）；企业微信使用原生流式消息，超长或接近单流时限时自动切分续流；Telegram 优先使用 `sendMessageDraft`，不支持时降级为编辑消息；Discord 与 Slack 原地编辑消息更新；微信在每段文字完成后立即发出。
- 发送过程按各平台速率限制节流并保持消息顺序，超长内容自动分段；任务被新消息打断或手动停止时会自动收尾当前流式消息。

## English

### Encrypted Vault

- A new Vault tab in Settings encrypts logins, contact details and addresses, payment cards, SSH keys, API keys, and custom secrets using OS-backed encryption (macOS Keychain / Windows DPAPI), with on-demand TOTP code generation and no plaintext fallback.
- Vault items are shared across all Bots by default (or scoped to specific Bots) while keeping secret values completely hidden from the model—Bots only see titles, field names, and masked previews. When referenced via placeholders, the main process decrypts on use at the execution boundary to blind-inject into work computer desktop, host desktop, terminal sessions (environment variables and ephemeral read-only SSH key files with automatic passphrase handling), Python environment variables, or MCP calls, while redacting outputs, accessibility text, logs, memory capture, and diagnostics.
- Add secrets either through secure in-chat input cards (`vault_request` on desktop and paired mobile PWA, bypassing chat history entirely) or directly in conversation (`vault_save`), which automatically masks tool records and scrubs plaintext from chat history after saving.
- Per-item human approval policies (auto, auto when bound, ask once per run, always ask) guard every use, flagging domain, app, or MCP mismatches and keeping an audit trail. Payment cards are restricted to desktop input only and always require explicit human confirmation. Full backups (`.aelionbackup`) migrate Vault secrets with password sealing, while exported Bot files (`.aelionbot`) never contain Vault data.

### Streaming replies in IM connectors

- Intermediate progress turns and final answers in IM chats now stream live as the Bot writes instead of waiting for the entire run to finish, hiding unclosed chart or widget fences mid-stream and formatting them as readable text once complete.
- Each platform streams using its best available mechanism with automatic fallback: Feishu uses CardKit streaming cards (adding `cardkit:card:write` to QR and manual setup, falling back to in-place card updates when unavailable); WeCom uses native streaming messages with automatic rollover on size and lifetime limits; Telegram uses `sendMessageDraft` and falls back to editing messages when unsupported; Discord and Slack update messages in place; and WeChat delivers each text turn as soon as it finishes.
- Updates are throttled to respect platform rate limits, kept in chronological order, split cleanly when exceeding message limits, and closed gracefully when a run is interrupted or stopped.
