# AelionBot v0.30.0

## 简体中文

### 1. 工具输出截断

- 新增 `electron/core/tool-output.ts`。过大的工具结果不再简单截取 JSON 前 6,000 个字符，而是优先保留整体结构和较短字段，如退出码、sha256 和分页信息，只对过长字符串从中间截短。
- 日志、stdout、stderr 等内容保留更多尾部信息，避免遗漏末尾的报错。过大的列表按条目数缩减；完整结果仍可通过 `read_result` 分页读取。
- 内联结果预算随模型上下文窗口从 6k 调整到 24k 字符。文件读取的默认分页同步缩小，减少默认读取结果再次被截断的情况。

### 2. 编辑功能

- 编辑和补丁依次尝试精确匹配、忽略行尾空格、忽略缩进，以及将弯引号和各种破折号归一化。宽松匹配默认仍须唯一；显式要求全部替换时按该选项处理。
- 缩进不同时，替换文本会适配文件原有缩进；完全没有匹配项时，错误信息提供附近相似行。
- 修复混合换行符处理：一个 CRLF 不再让整个文件转换为 CRLF，每行保留自己的原始换行形式。
- Patch 支持没有前导空格的空白上下文行，以及 `@@ some line` 形式的位置锚点。VM Python patch 脚本同步这些行为，并增加宿主端与 VM 端一致性测试。
- 多文件 patch 失败后，只要涉及的每个文件最终都成功写入，对应失败状态便会清除，不再持续阻止任务完成。

### 3. 压缩与上下文管理

- Compaction 请求追加到正常对话末尾，以复用供应商已缓存的前缀。模型若在压缩中尝试调用工具，则回退到原有的无工具处理方式。
- 摘要新增“用户的原始请求”和“修改过的文件”。摘要超过目标大小时在本地缩短，不再额外调用一次模型。
- 统一 prompt 与 validator 的长度规则。
- 大上下文保留更多历史：1M 上下文的原文尾部预算从 24k 提升至约 118k，摘要预算从 3k 提升至 8k；160k 及以上窗口预留 8k 输出。
- 启用 Anthropic thinking 时，其 token 预算最多占输出预算的一半，同时移除不兼容的自定义 temperature。
- 群聊上下文统计不再覆盖主聊天的统计。

### 4. 缓存与项目指令

- 在 Git 项目内，从仓库根目录到所选目录逐层读取并合并 `AGENTS.md` / `CLAUDE.md` 等项目约定；同目录使用优先级最高的文件。
- 总长度最多 32k 字符，截断或省略上级规则时明确提示。更具体的子目录规则后置，且不会扩大权限或替代用户要求。
- 项目约定作为需要遵守的开发、测试与验证规则，放入稳定的 reference block，避免每次运行重复追加。
- System message 中的用户请求副本最多保留 4,000 字符；完整请求仍保存在聊天历史中。

### 5. 中文历史搜索

- 支持“压缩”“失败”等两个汉字词语。
- 一条记录覆盖的搜索词越多，排序越靠前。

### 6. MCP

- 响应服务器的工具列表变化通知，及时更新可用工具。
- 工具列表过大时，先提供精简信息，再按精确工具名称获取完整 schema。
- 工具结果与资源明确标记为“不可信数据”；服务器返回字段不能覆盖该标记。

### 7. 性能

- 批量发送 UI 状态更新；流式更新仅发送正在生成的回复，不再每次传输完整应用状态。
- 存储行使用实体 ID，而非数组位置作为 key。20,000 条消息的基准场景中，插入或删除一条消息的行写入次数从 19,994 次降至 2 次。
- 兼容旧格式数据，并在下一次保存时迁移为新格式。

### 清理

- 移除根目录遗留编译文件、独立游戏预览页面和启动脚本、失效的预览命令及旧试玩说明。正式游戏实现与回归测试保留。

## English

### 1. Tool output truncation

- Added `electron/core/tool-output.ts`. Large results no longer use only the first 6,000 characters of JSON. The compactor prioritizes structure and short fields such as exit codes, SHA-256 hashes, and pagination metadata, shortening long strings in the middle.
- Logs, stdout, and stderr retain more trailing content so errors at the end remain visible. Oversized lists are reduced by item count; full results remain available through paginated `read_result` calls.
- Inline budgets scale from 6k to 24k characters with the model's context window. Smaller default file-read pages reduce unnecessary truncation of ordinary reads.

### 2. Editing

- Edits and patches try exact matching, trailing-whitespace normalization, indentation normalization, and typographic quote/dash normalization in order. Fuzzy matches must be unique by default; an explicit replace-all option is respected.
- Replacement text adapts to the file's existing indentation. Failed matches include nearby similar lines.
- Mixed line endings are preserved per line instead of converting an entire file to CRLF because one CRLF was present.
- Patches accept blank context lines without a leading space and `@@ some line` location anchors. The VM Python patch implementation follows the same behavior, with host/VM parity tests.
- Failed multi-file patches no longer block completion indefinitely once every affected file has subsequently been written successfully.

### 3. Compaction and context management

- Compaction instructions are appended to the normal conversation to reuse the provider's cached prefix. If the model attempts tool calls during compaction, the request falls back to the previous tool-free path.
- Summaries now include the user's original requests and modified files. Oversized summaries are shortened locally without an additional model call.
- Prompt and validator length rules are aligned.
- Large windows retain more history: at 1M context, the verbatim tail grows from 24k to approximately 118k tokens and the summary budget from 3k to 8k. Windows of 160k or more reserve 8k output tokens.
- Enabled Anthropic thinking uses at most half the output budget, and incompatible custom temperature settings are omitted.
- Group context statistics no longer overwrite the main conversation's statistics.

### 4. Caching and project instructions

- Within Git projects, instructions such as `AGENTS.md` and `CLAUDE.md` are merged along the path from the repository root to the selected directory, using the highest-priority file in each directory.
- The combined text is capped at 32k characters, with explicit notices when content is truncated or parent rules are omitted. More specific rules appear later and cannot expand permissions or replace user requirements.
- Project instructions are treated as development, testing, and verification rules in a stable reference block instead of being appended again on every run.
- User-request copies in system messages are limited to 4,000 characters; the full request remains in conversation history.

### 5. Chinese history search

- Two-character Chinese terms such as “压缩” and “失败” are searchable.
- Records matching more query terms rank higher.

### 6. MCP

- Tool lists refresh when servers announce changes.
- Large catalogs provide compact metadata first; complete schemas are fetched by exact tool name.
- Tool results and resources are explicitly marked as untrusted data, and server-returned fields cannot override that marker.

### 7. Performance

- UI state updates are batched. Streaming updates send only the replies currently being generated instead of the entire application state.
- Storage rows use entity IDs rather than array positions. In the 20,000-message benchmark, inserting or deleting one message reduces row writes from 19,994 to 2.
- Existing data remains readable and migrates to the new format on the next save.

### Cleanup

- Removed legacy root build output, standalone game-preview pages and launch scripts, the obsolete preview command, and old playtest instructions. Production game functionality and regression tests remain available.
