# AelionBot v0.42.1

这一版把文件、检索和命令收成同一套工具。不填 location 就是这台电脑，只有明确写 vm 才进入 Linux 工作电脑。模型调用这些工具时不再填写 reason。

## 简体中文

### 工具

- 文件、目录、搜索和命令不再分成带 host_ 的另一套名字。`file_read`、`file_write`、`file_patch`、`list_directory`、`find_files`、`search_files` 和 `exec_command` 默认操作这台电脑；`location=vm` 才使用工作电脑。
- 这些工具，以及看图、抽帧、生图、预览和补丁，不再向模型要求 reason。需要你确认时，审批说明由命令、路径或补丁中的文件清单生成。
- `exec_command` 会在短时间后交还控制权，进程继续运行。用 `write_stdin` 继续输入或查看输出，用 `exec_stop` 停止。命令正文如果是补丁，会直接应用，不会进入 shell。
- 同一批里的文件写入按顺序执行。前面的写入被拒绝后，后面的写入不会启动。
- 旧对话里的 `host_file_*`、`host_execute` 和 `computer_execute` 仍按原来的记录显示。

## English

### Tools

- File, directory, search and command tools no longer have a separate host_ set. `file_read`, `file_write`, `file_patch`, `list_directory`, `find_files`, `search_files` and `exec_command` operate on this computer unless `location` is `vm`.
- Those tools, plus image view, video frames, image generation, preview and patch, no longer ask the model for a reason. Approval text is generated from the command, path or patch file list.
- `exec_command` returns control after a short wait while the process keeps running. Continue or poll with `write_stdin`, and stop it with `exec_stop`. A patch in the command is applied directly instead of being sent to the shell.
- File writes in one batch run in order. If an earlier write is denied, later writes in that batch do not start.
- Older transcripts still render `host_file_*`, `host_execute` and `computer_execute` records.
