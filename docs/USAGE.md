# 使用帮助

这里补充工作目录、任务规划与操作许可的具体使用方式。

## 工作目录、计划与目标

- 输入框左下角的 **＋** 可以上传附件、制定计划或执行目标。把文件夹拖进输入框，可以打包成附件发送。
- 工作目录在 **Bot 资料**、**群聊设置**或**工作会话设置**里修改，按单聊、群聊或工作会话分别保存；本机命令的默认目录和文件的相对路径使用该目录。已经开始的任务保留原目录，更换目录不会增加操作权限。
- 输入 **`/plan 任务内容`**，Bot 先调查并生成带有验收条件的步骤清单。计划显示在输入框上方，点击 **开始执行** 后才允许实际修改项目。
- 输入 **`/goal 目标内容`**，Bot 会建立目标并持续执行、核对结果；遇到阻碍会说明原因。卡片支持暂停、继续、查看步骤和完成依据。达到运行预算或应用退出时保留进展，不自动重复执行。
- Bot 也能在已授权的任务范围内主动设置计划或目标，使用同一套步骤、执行记录和权限机制。输入 `/` 可以选择指令，附件、粘贴和 `@` 提及仍然可用。

## 本机权限模式

在 Bot 主会话输入框底部选择权限模式。设置按 Bot 保存，从群聊接下的工作也跟随这个设置，群聊没有独立的权限选择。

- **每次询问**：命令、文件和 MCP 调用每次等待确认，不套用自动放行规则。
- **自动审批**：工作目录内普通文件的读取、创建、编辑，以及可明确识别的简单文件命令，由本地规则直接放行，不消耗审核模型 Token。敏感配置、越界写入、MCP 调用和其他未匹配的操作交给应用的默认模型审核。你已保存的命令规则仍可生效；模型审批本身不产生长期权限。
- **完全访问**：Bot 的本机操作和 MCP 调用直接执行。VM 人工接管仍需要你处理。

自动审核不放行、未配置默认模型或审核失败时，会回到会话内请你确认。切换模式会重新处理尚未执行的请求，取消任务会撤销审核，过期的审核结果不能继续执行操作。

项目内编辑采用本地规则的设计参考了 [Claude Code 的权限模式](https://code.claude.com/docs/en/permission-modes) 和 [Gemini CLI 的写入策略](https://github.com/google-gemini/gemini-cli/blob/main/packages/core/src/policy/policies/write.toml)。本机权限模式是应用的执行审批层，不是操作系统沙箱。

## 本机电脑控制

在 设置 → 权限 打开“让 Bot 操作这台电脑上的应用”后，Bot 可以观察并操作这台 Windows 电脑上的应用窗口。它默认关闭，目前只支持 Windows。

- **前台运行**：Bot 使用真实的鼠标和键盘，操作期间你不能同时使用这台电脑。屏幕边缘的边框和顶部的提示条表示 Bot 正在操作，按 `Esc` 立即停止这次任务。需要后台并行的工作交给工作电脑。
- **每个任务确认一次**：任务第一次要操控电脑时，会话里会出现确认卡片。允许之后，这个任务里不再询问，直到它结束；下一个任务会重新询问。这项确认与本机权限模式无关，完全访问模式下同样需要你确认。拒绝之后，这个任务不会再次询问。
- **不能操作的窗口**：终端应用、AelionBot 自身、以管理员身份运行的窗口，以及系统的权限和安全提示。Bot 遇到这些步骤会请你处理。Windows 键组合和 `Alt+Tab` 这类会离开当前应用的快捷键也不会发送。
- **只看到被操作的应用**：截图只包含目标应用自己的窗口，点击和输入落到其他应用上时会被拒绝。截图会发送给当前 Bot 使用的模型服务。
- **同时只有一个任务**：一个任务占用这台电脑时，其他任务的电脑操作会等待。无人值守运行不提供这个能力。

这套行为对齐了 [Codex 的 Computer Use](https://learn.chatgpt.com/docs/computer-use)：按窗口观察和操作、前台独占、终端和自身不可操作。Codex 按应用逐个批准，这里改为每个任务进入时确认一次。

工作电脑和本机的电脑操作都支持 `batch`：Bot 可以在一次观察后连续执行多个不会改变界面布局的动作（例如点击输入框、输入、回车），只在最后截一张图。
