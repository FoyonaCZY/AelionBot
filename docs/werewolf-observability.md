# 狼人杀可观测性与问题记录

2026-09-21。后续更新：新局已改为七人并加入女巫；开局随机分配并保存性格，延长发言，运行记录已改成人名与中文动作展示。下文六人阶段的问题记录保留为历史，策略状态仍待实现。

当前优先目标是能解释一局如何推进、为什么超时、模型看到了什么和提交了什么。以下区分已复现并修复的问题、当前记录能力，以及尚未实现的玩家策略。

## 如何查看

对局右上角「运行记录」。全 AI 对局可在运行中查看；真人局运行时只展示可见公共记录，结束后允许查看完整决策记录。

记录按对局、请求 ID、玩家、尝试次数关联：创建请求 → 请求模型 → 模型返回或失败 → 动作采纳或过期丢弃 → 阶段推进。另记录超时、暂停、继续、结束和重启恢复。模型输入记录发送给该玩家的角色投影和规则提示，不使用全局身份表代替玩家视角。

可查看模型名称、尝试次数、每次返回/失败耗时、解析后的动作和非法目标等校验失败原因。本地试玩服务保留 HTTP 状态码，未透传可能带凭证的任意服务商错误。界面支持按玩家筛选，输入内容默认折叠。平均耗时只统计成功返回的尝试，不代表整轮等待时间。

完整记录保存在已有私有对局文件中，正常玩家读取接口不返回 trace。私有诊断写入不改变公共状态版本；迟到响应被记录，但不改变终局结果。模型密钥不进入提示和 trace。

## 当前边界

- 旧对局没有历史模型输入和耗时，不能补录或倒推。
- 这是决策链路记录，尚不是可从任意事件重建状态的事件存储。还没有逐步回放、导出、保留期限或日志压缩。
- 记录解析后的动作，不记录原始 HTTP 响应、token 用量、流式首字耗时。非法 JSON 可以定位到请求和输入，但不能还原原始输出。
- 真人局运行时不暴露其他玩家调用明细，避免夜间请求类型泄露身份。
- 磁盘写入失败会停止推进，但不能承诺把磁盘故障自身成功写入同一块磁盘。
- 仍是六人简化规则。按座位发言、固定短发言、夜间无狼队讨论等节奏与机制没有在本次改变。

## 下一步：让玩家拥有持续策略

代码现状：所有 AI 共用规则提示，只笼统要求按阵营获胜和狼人伪装。每轮有可见历史，但没有单独保存的私人判断、宣称身份或计划。现阶段不能声称玩家具备稳定的欺诈和带队能力。

后续沿用“参与者自己的上下文”，分清三种信息：规则确认的事实、玩家自己的判断、对外选择表达的说法。三者不能互相覆盖；狼人可以对外说谎，但不能让谎言变成裁判确认的事实。

每个玩家需要保存简短的结构化策略状态：当前公开身份、怀疑对象及置信度、当前投票意向、下一步目标。它是游戏状态摘要，不要求模型输出内部思考过程。新的发言和投票触发更新；更新必须留下版本记录，复盘时才能检查其是否回应了新证据。

在此基础上让行为产生差异：有的主动提出放逐目标，有的追问矛盾，有的谨慎跟票。狼人根据局势选择掩护队友、转移怀疑、假报身份或切割；预言家权衡何时公开查验；村民区分已知事实与他人宣称。不能要求每轮固定欺诈，也不能靠形容词保证策略质量。

验收需要固定局面和多局模型实测：是否回应前人、是否维护自己的宣称、是否因新证据改票、是否泄露队友、是否利用合法谎言争取阵营利益。规则测试通过只能说明动作合法和流程可推进，不能说明这些能力已实现。

## 验证范围

本次 20 项规则与运行测试通过，包括 100 局随机合法动作完整结束、真人各身份、并发、暂停恢复、超时、终止后迟到响应、trace 的请求关联和私密访问限制。浏览器隔离 Mock 检查覆盖三项同步/错误问题及诊断面板输入、耗时、动作展示。生产构建通过，保留已有大 chunk 警告。本次没有重新跑付费模型整局，未据此评价真实 Grok 策略质量。

## 首夜刀中预言家审计与角色技能（2026-09-21）

检查本机两局有完整 trace 的真实对局：四次狼人请求分别来自两局的两名狼人，均在首夜选择了本局预言家；两局预言家位置不同。四份输入只带自己与狼队友的角色，没有预言家身份、查验结果、别人的待办或夜间答案。更早四局没有 trace，无法逐条追溯。没有查到直接身份泄露，不能据此断言两个命中是巧合或排除所有未知路径。

发现模型输入原先包含对手性格、Bot 职业名称、全局时钟及运行版本等非必要字段。本次改为显式允许字段：当前日/阶段、座位与存活信息、自己身份和性格、可知的狼队友、本人可见事件、本次合法动作。模型使用中性座位称呼；事件中的 Bot 名称同步改为座位称呼。合法目标展示次序按请求做稳定打散，减少固定首项偏好，不改变合法目标集合，也不替模型选目标。

新增反事实测试：保持狼人已知事实不变，交换其他人的神职与村民身份、改变对手性格、药剂余额、私人查验和外部请求时钟，狼人输入和加载的技能必须逐字不变。另覆盖七名玩家各自私有日志隔离、字段白名单、目标排序、角色技能选择，以及 trace 确实包含技能信息。31 项狼人杀测试通过；这些检查证明已测路径，不是模型公平性或长期命中率评测。

攻略存于 `assets/game-skills/werewolf/`。每次请求读取缓存的通用 SKILL.md 与本人的身份文件，组装到实际 system/instructions；Electron 和本地试玩使用同一个组装函数，打包包含技能资源。技能内容散列作为版本随 trace 保存，完整实际指令也保留；运行记录以中文展示“已读攻略”。修改文件后重启服务加载新版本。无须模型自行调用文件工具。

来源包括网易官方战术术语说明与三篇口袋狼人杀文字攻略，详见该目录 `references/sources.md`。已排除面杀观察、特殊狼、警徽、自刀、自爆、屠边等不适用部分。本次没有观看视频，不把搜索摘要当成观看结果。技能提供角色策略，不包含任何对局隐藏身份。

## 上下文来源记录

模型输入已拆为 `context.shared` 与 `context.personal`。前者包含公开座位、存活状态、阶段和公共事件，不含真实角色；后者包含开局授权的本人身份、本人性格、规则授权的狼队友和私有事件。狼队友信息来自服务端规则的个人视角投影，不来自全员共享上下文。

来源标识随每次 `model_started.input` 原样持久保存：本人身份为 `role_assignment`，狼队友为 `wolf_team_visibility`，公开事件为 `public_event`，经权限过滤的私有事件为 `authorized_private_event`，本人的行动请求为 `private_action_request`。不把其他人的私有事件读者列表发给模型。运行记录以中文呈现两块上下文及其授权来源。

旧 trace 没有这些来源字段，界面明确显示“来源未标注”，不根据现在的代码反向伪造历史来源。新增测试检查全部七名玩家共享上下文完全相同，且狼队友、查验、用药等私有事件只出现在授权玩家的个人上下文；与原有反事实测试共同回归。
