# Harness 升级实施记录

2026-09-07。依据 [Hermes 源码对照](Harness-Hermes-Comparison-20260907.md)，将适合 AelionBot 长期 Bot、单聊、群聊和工作电脑的机制落实到 TypeScript 内核。本文的 v05 是设计阶段编号；这些改动随应用 v0.5.0 发布。

## 已落地的机制

| 项目 | 实现与验收 |
| --- | --- |
| 技能与 MCP 权限 | 注册技能的正文、资源读取与复制到工作电脑不再逐次确认。已启用 MCP 的发现、资源、提示模板及明确声明只读且非破坏性的工具可直接使用。其他 MCP 调用展示具体工具和参数，保留拒绝及本机命令规则；配置指纹变化会使旧的调用检查失效。 |
| 执行证据 | 每次调用独立保存 executionId、操作目标、结果引用及状态。同类工具对另一文件成功，不再清除之前的失败。未知结果需要后续核验并记录处理依据；启动时不重放副作用操作。执行卡片按明确的处理记录显示“已处理”。 |
| 请求恢复 | 408/409/429、服务错误、连接故障和空响应支持有界重试与可取消退避；尊重 Retry-After。流中断重试前重置预览，不拼接两次回答；完整解析后才交出工具调用。截断不会执行半份参数。认证及普通参数错误不盲目重试。备用模型只在用户配置的同一 Provider 内切换。 |
| 模型协议 | Provider 可选 Chat Completions、Responses、Claude Messages、Gemini Generate Content；旧配置默认保持兼容接口。可配置温度、推理强度/思考预算及备用模型。原生推理项、签名和工具标识保留，跨 Provider/模型不重用不兼容原生状态；模型列表支持原生鉴权和分页。辅助用途有独立输出及超时参数。 |
| 预算与计划 | 设置增加“运行”：轮数、时长、Token 预算、模型重试、单次超时/输出、读取并发及进度间隔。默认 120 轮、60 分钟、500000 Token；轮数可设 0，时间与用量仍受约束。任务清单保存目标、步骤、验收、版本和证据，未完成步骤阻止提前完成。兼容同工作区正在加入的计划/目标及继续执行功能。 |
| 批处理与程序化执行 | tools_batch 支持有限并发的独立读取和声明依赖的结果传递；预先校验所有步骤，不接受命令、写入、界面动作。嵌套结果引用不执行任意 JavaScript；每步有执行记录。其他普通工具调用保持串行。 |
| 后台进程 | host/VM 可启动任务或服务，返回独立句柄，支持日志分页、查询、等待、停止；本机命令继续经过权限检查。任务不能只凭启动成功完成。停止通过自己启动的 supervisor 控制子进程；未知状态不假定成功。VM 启动标识变化用于识别已被重启终止的进程。 |
| 持续 Python 会话 | 每 Bot 的 VM 会话保留变量与已加载数据，支持执行、轮询和重置。未完成请求不能重复提交，代码异常不销毁会话；取消执行会停止相应会话。输出有上限。大代码、文件内容和恢复数据通过 SSH 标准输入传输，避免命令行长度限制。 |
| 上下文 | 单聊和群聊共用 ContextEngine 的 Token 计量与校准、完整工具交换、旧输出裁剪、结构化摘要、一次格式修复、失败冷却、原文指纹和原子压缩版本。会话分开保存摘要边界，保留群消息身份与实际发布记录；任务状态参与预算计算。 |
| 用量与进度 | 保存请求用途、Provider/模型、输入/输出、缓存、推理 Token 与耗时；未提供用量时保留估计值。前台、压缩、复盘和阶段汇报可追踪。汇报要求有新结果且达到时间间隔，不再每三个工具调用无条件额外请求模型。 |
| 技能治理 | 当前上下文已有相同版本完整正文时不重复载入；压缩移除正文后可以重读。内容不变不新增版本或提升知识修订号。支持精确文本替换、资源维护及覆盖指纹、读取计数、置顶、归档、恢复和版本恢复。后台仍可判断“不值得保存”，不强制沉淀。 |
| 持久化与文件恢复 | 正式应用使用 state.sqlite 按变化的消息、运行及上下文记录增量写入，事务失败保留旧状态。state.json 用作迁移输入与正常退出时的兼容导出。文件检查点默认关闭；开启后支持 file_write/host_file_write 的单文件旧版本（最多 2 MB），恢复前核对当前指纹，拒绝覆盖之后的修改，本机恢复仍需确认。 |
| 协作委托 | bot_delegate_task 保存明确目标、验收条件与预期成果；接收方自行决定是否转入主会话，执行后提交完成/受阻回执。完成回执必须引用自己的成功执行记录。发送方可查回执、回复中实际分享的附件和用量；排队成功与完成分开表达。 |

## 边界

- 这是对执行机制的移植与重写，保留 AelionBot 的长期身份、私有知识和群聊设计。Hermes 的 CLI、消息网关、云运行后端及外部记忆服务接入没有整体搬入桌面应用。
- 批量工具链目前限于读取；持续 Python 会话在工作电脑执行，不给内存会话额外的本机或 MCP 权限。
- 检查点覆盖文件工具的修改，不是整个 VM、整个项目或 Git 分支快照，也不涵盖 shell/GUI 所有文件改动。没有自动操作用户 Git 仓库或发布。
- 同一进程句柄的未知结果需要核查；重启应用/VM 不会自动重放原工具调用。独立 Bot 桌面仍共享一个 VM，不表示 OS 用户权限完全隔离。
- 技能实现精确内容去重与版本治理，不宣称已经解决任意语义近似技能的自动合并。
- Token 预算按请求记录检查，未知用量使用估计；它不等同于供应商的货币账单。SQLite 写入已增量化，内存状态比较与渲染层快照仍有进一步优化空间。

## 验证

独立场景覆盖：跨目标失败不被掩盖、同目标重试、未知结果恢复、超过 30 轮的任务、429/断流/取消、原生推理及签名保留、技能/MCP 只读免确认、副作用调用拒绝、批处理依赖与并发、技能无变化不写版本、归档恢复、SQLite 增量写入与重开、后台进程跨管理器读取与停止、Python 变量保留与异常恢复，以及大文件经标准输入写入和恢复。

使用临时文件、实际本机测试子进程、独立 Python 运行时、模拟模型接口和 MCP fixture。没有连接用户的现有 VM 或真实模型账户。原生供应商兼容性由协议模拟场景验证，真实供应商/真实 VM 的端到端验收仍需部署后进行。

最终验证结果以本次任务附带的测试与构建日志为准；工作区 output/harness-upgrade-final-tests.log 和 output/harness-upgrade-build.log 为本地检查日志，不进入发布包。
