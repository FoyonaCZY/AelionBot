# 设计任务质量与交付失败排查

任务：帮我设计一个加密货币交易行的官网。任务 ID：`d66daaae-232a-4780-93c8-ee54891bf310`。

## 结论

这是模型工具使用错误、工具接口易误用和工作流恢复策略共同造成的退化。自动预览缺参是 AelionBot 的确定性代码错误。不能用这次被多轮失败打断的结果判断模型的设计能力上限，也不能据此保证换一个模型即可解决。最初生成稿本身仍比较模板化，工具修复并不等于已经证明视觉质量足够好。

## 证据来源

只读检查了该任务的 designer/state.json、state.sqlite 中对应运行与用量记录，以及默认工作目录中的 index.html 和 assets/tokens.css。没有修改用户原任务、运行记录或模型配置。

运行记录显示模型标识为 `gpt-5.6-luna`，不是对供应商实际底层模型的独立鉴定。开始于 2026-09-15 19:05:08 UTC，结束于 19:14:08 UTC，约 9 分钟；运行计数为 22 轮模型调用、21 次顶层工具调用。

1. 5 次 host_file_write 全部失败。前几次新建文件提供了全零或重复 0c 的虚构 expectedSha256；最后一次把读取返回哈希中的 `724ade1` 抄成了 `7247241`。Host 文件保护正确拒绝了这些操作。没有证据表明用户并发修改了这些文件。
2. 初次生成 index.html 为 11,300 字符，最终交付 3,915 字符；首次拟写入样式为 8,018 字符，最终样式为 3,743 字符。大小本身不衡量质量，但实际丢失的功能可确认。
3. 模型改用 host_execute 后，又提交了一个 9,477 字符的命令，超过工具的 6,000 字符限制。随后以较短 shell 命令重写页面与样式。
4. 在相同的 1440×900 浏览器视口对比原始工具调用中的首稿与最终磁盘文件：首稿链接是自定义深色且无下划线；交付稿为浏览器默认蓝色下划线。两稿样式表均被正确加载，不是整个 CSS 请求失败。
5. 首稿存在 focus 样式和 4 个 data-design-id；交付稿两者均丢失。600px 宽度下点击菜单后 class 已变为 `links open`，computed display 仍为 none，原因是缺少展开态样式。
6. 多个注册/交易按钮没有交互处理；静态行情被写成 LIVE MARKET，并加入没有来源的稳定性指标。模型最终文字还声称支持键盘焦点等未验证内容。
7. design_publish 自动调用 open_preview 漏了 schema 必填 reason。使用真实 Harness、Attachments、ArtifactService 和 AgentPreviews 的回归测试，在修复前分别对 HTML 和 PPT 复现相同错误，修复后均通过。

用量记录有 23 条 foreground 请求，其中 22 条返回 usage：累计输入 908,678 token、输出 20,073 token；另有 4 条审批请求。累计输入包含反复发送的上下文，不等于独立内容量或实际计费量。供应商没有返回缓存 token 字段，不能把缺失字段当作缓存命中为零。

## 工作流问题

- 新建和覆盖共用一个文件工具，模型误填可选哈希后收到“文件变化”提示，容易进入错误的冲突恢复循环。
- 没有明确要求失败恢复保留原设计，模型转用有长度限制的 shell，并主动缩减页面。
- 已注入的设计参考仍被重复读取；旧引用截断又没有显式完整性标识，增加重复上下文。
- “尽快交付初版”的约束比排版、视觉系统落地和基本交互要求更具体，容易促成低完成度模板。无需复杂验收不应等于放弃控件样式与交互。
- 原测试没有启用自动预览分支，覆盖了生成文件却没有覆盖完整交付路径。

## 本次修复

- 为自动 open_preview 补充明确 reason，保留真实 schema 验证。
- 增加 design_file_create：新建文件只需要 path、content、reason，不暴露哈希或覆盖参数。底层仍使用已有 Host 写入权限、检查点和防覆盖保护。
- 新文件错误填写哈希时返回准确提示；不把虚构哈希当成有效版本，不放松覆盖保护。
- host_execute schema 明确 maxLength=6000，和实际执行限制一致。
- 原型工作流要求先确定排版层级、区块节奏和主视觉；控件需有明确样式和原型行为，示例数据需标注；工具失败不应缩减设计内容。保持轻量检查，不新增复杂验收流水线。
- 参考上下文保留更完整的 DESIGN.md，移除 tokens.css 注释以减少冗余，同时显式标记 referenceTruncated；已提供完整参考时不重复读取。

## 验证边界

真实本机服务回归验证了创建超过 shell 限制的页面、文件内容完整保留、防止覆盖、预览排队、PPTX 可编辑交付及 VM 零调用。浏览器比较使用原始生成代码的分析副本，没有重新调用模型或重写用户页面。

本次没有做跨模型 A/B 对比，未宣称修复后的真实模型输出已经达到目标美学质量。原任务仍保留，旧本地程序包也未自动替换。
