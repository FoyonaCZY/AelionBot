# 保险库（Vault）设计方案

状态：设计完成，待实现（2026-11-25）。代码实现交由 Hydrogen 按本文档分阶段落地。

目标：为 AelionBot 提供类似 Grok Bot Vault 的全局凭据与个人信息保险库。用户可通过安全表单、设置页或直接对话将邮箱、地址、网站登录、支付卡片、SSH 密钥、API Key 等信息存入保险库；**所有 Bot 默认可直接调用，但模型全程看不到明文内容**，仅能在操控电脑（工作电脑 VM / 本机桌面）或调用授权工具时，由主进程在执行边界完成盲注（Blind Injection），用于注册登录网站、自动填表、SSH/Git 操作、调用 API 与 MCP 等。

---

## 一、核心原则与安全不变量

实现过程必须始终满足以下 5 条不可违反的不变量：

1. **模型零可见（Zero-Exposure to LLM）**
   - 任何保险库字段的明文都不得出现在系统提示词、轮次上下文、工具返回值、错误信息、`ExecutionLedger`、`results/*.json`、对话历史（`conversations` / `groupContexts` / `peerContexts`）、摘要（`summaries`）、长期记忆（`MemoryCapture` / `Cognition`）或诊断导出中。
   - 不向模型提供任何“读取明文”或“删除条目”的工具；模型仅能看到条目的**元数据目录**（ID、标题、分类、字段名、安全掩码预览、适用域名/服务）。
2. **执行通道最小化（Sink Capability Matrix）**
   - 不同类别的数据只允许注入其合理通道：例如**支付卡信息仅允许进入桌面输入通道（`computer` / `host_computer`）**，严禁展开到 Shell、Python、文件写入、MCP、聊天发送或网页 URL 中。
   - SSH 私钥不以明文字符串拼接进命令行，而是通过**临时只读文件（`0o600`）+ 环境变量路径 + 执行结束即销毁**的机制注入。
3. **只有人类授予高敏授权（Human-in-the-Loop）**
   - 延续 AelionBot 的权限哲学：高敏操作（如使用支付卡、首次在任务中使用登录凭据/SSH/API Key、或在绑定域名/应用之外使用）必须由人类通过交互卡片批准，**自动审核模型（`HostApprovals`）不得代为放行**。
4. **按需解密与最小驻留（Decrypt-on-Use）**
   - 元数据与密文分离存储；列出目录、搜索条目、渲染设置列表均不解密。仅在真正注入或用户本机显式查看时按单条解密。
   - VM 桌面粘贴明文后立即清空剪贴板；临时 SSH 密钥文件落入内存 tmpfs 并在进程退出/取消时覆写删除。
5. **全 Bot 共享、导出隔离**
   - 保险库属于当前用户的全局数据，默认所有 Bot 均可调用（支持可选按条限制可用 Bot）。
   - 整机备份（`.aelionbackup`）经 `backup-secrets.ts` 口令封包迁移；单个 Bot 导出（`.aelionbot`）**绝不包含**保险库数据。

## 三、数据模型与分类体系

新增共享类型文件 `shared/types/vault-types.ts` 与纯引用解析工具 `shared/vault-refs.ts`（无 React/DOM/Node 专有依赖，双进程与手机端共用）。

### 3.1 分类与预设字段模板

| 分类 (`VaultCategory`) | 典型用途 | 推荐预设字段（也允许自定义字段） | 默认访问策略 (`VaultAccessPolicy`) | 默认允许通道 (`VaultSink[]`) |
| --- | --- | --- | --- | --- |
| `login` | 网站/应用账号登录 | `username`, `email`, `password`, `totpSecret`, `recoveryCodes` | `ask-once-per-run` | `vm_desktop`, `host_desktop`, `exec_env`, `exec_inline`, `mcp` |
| `contact` | 个人资料、邮箱、收货/账单地址 | `fullName`, `email`, `phone`, `addressLine1`, `addressLine2`, `city`, `state`, `postalCode`, `country`, `company` | `auto` | `vm_desktop`, `host_desktop`, `exec_env`, `exec_inline`, `python_env`, `mcp` |
| `card` | 信用卡/借记卡支付 | `cardholderName`, `cardNumber`, `expMonth`, `expYear`, `expiry`, `cvv`, `billingAddress`, `billingPostalCode` | `always-ask` | **仅限** `vm_desktop`, `host_desktop` |
| `ssh_key` | SSH / Git 认证 | `privateKey`, `passphrase`, `publicKey`, `username`, `host`, `port` | `ask-once-per-run` | `exec_file`（`privateKey` 强制文件化）, `exec_env`, `vm_desktop`, `host_desktop`（`publicKey`/`username`/`host`） |
| `api_key` | API Token / SDK 密钥 | `apiKey`, `apiSecret`, `baseUrl`, `orgId`, `headerName` | `ask-once-per-run` | `exec_env`, `python_env`, `exec_inline`, `mcp`, `vm_desktop`, `host_desktop` |
| `secret` | 任意机密/证件/自定义键值 | 用户自定义键值（`value` 或任意 `^[a-zA-Z][a-zA-Z0-9_]{0,47}$`） | `ask-once-per-run` | `vm_desktop`, `host_desktop`, `exec_env`, `python_env`, `mcp` |

> **关键设计**：遵循用户要求“保存后所有 Bot 都看不到具体内容”，**即便是 `contact`（邮箱、地址、手机号）也对模型盲注**——目录中仅展示安全掩码预览（如 `z***@example.com`、`上海市***`），不直接把明文塞进模型上下文。分类差异体现在**审批严格度**与**允许通道**，而非是否对模型公开明文。

### 3.2 TypeScript 契约（`shared/types/vault-types.ts`）

```ts
export type VaultCategory = 'login' | 'contact' | 'card' | 'ssh_key' | 'api_key' | 'secret';

export type VaultAccessPolicy = 'auto' | 'auto-when-bound' | 'ask-once-per-run' | 'always-ask';

export type VaultSink =
  | 'vm_desktop'
  | 'host_desktop'
  | 'exec_env'
  | 'exec_file'
  | 'exec_inline'
  | 'python_env'
  | 'mcp';

/** 影响脱敏与洗脱强度，不代表对模型明文可见；所有字段对模型默认盲注。 */
export type VaultFieldKind = 'text' | 'email' | 'phone' | 'password' | 'card_number' | 'cvv' | 'totp' | 'multiline_key';

export interface VaultFieldMeta {
  /** 字段键名，如 username / password / cardNumber / privateKey */
  key: string;
  /** 展示标签（可选），如 “卡号”、“私钥” */
  label?: string;
  kind: VaultFieldKind;
  /** 安全脱敏预览，绝不还原明文：如 "z***@example.com" / "•••• 4242" / "••••••" / "SHA256:ab12…" */
  preview: string;
  /** 是否属于短值（长度 < 6，如 3-4 位 CVV）；脱敏器据此避免全局子串误伤 */
  shortValue?: boolean;
  /** 虚拟派生字段标志（如由 totpSecret 派生的 totp） */
  derived?: boolean;
}

export interface VaultBinding {
  /** 绑定的网站域名（如 "github.com"）、主机名、本机应用名或 MCP 服务名 */
  kind: 'domain' | 'host' | 'app' | 'mcp';
  value: string;
}

/** 渲染进程与模型目录可见的纯元数据（永不含密文与明文）。 */
export interface VaultItemMeta {
  id: string;
  /** 可读短别名（小写字母/数字/下划线/连字符，全局唯一，如 "github-personal"） */
  slug: string;
  category: VaultCategory;
  title: string;
  /** 供模型判断何时选用该条目的简短非敏感说明，如 "日常注册网站用的主邮箱与收货地址" */
  notes?: string;
  tags: string[];
  bindings: VaultBinding[];
  fields: VaultFieldMeta[];
  policy: VaultAccessPolicy;
  /** 覆盖分类默认通道（可选，但不能绕过系统硬禁区） */
  allowedSinks?: VaultSink[];
  /** undefined 或空数组表示所有 Bot 可用；非空表示仅列表中的 Bot 可用 */
  botIds?: string[];
  /** 是否允许在定时自动化（scheduledRun）中无人工确认使用；card 类别强制为 false */
  allowInAutomation?: boolean;
  createdAt: string;
  updatedAt: string;
  lastUsedAt?: string;
  /** 仅当在另一台电脑恢复且未输入备份密码时为 true，提示用户重新录入 */
  unreadable?: boolean;
}

export interface VaultItemWriteInput {
  id?: string;
  slug?: string;
  category: VaultCategory;
  title: string;
  notes?: string;
  tags?: string[];
  bindings?: VaultBinding[];
  /** 明文字段键值；更新已有条目时仅传入修改的字段，值为 null 表示删除该字段 */
  fields: Record<string, string | null>;
  fieldKinds?: Record<string, VaultFieldKind>;
  policy?: VaultAccessPolicy;
  allowedSinks?: VaultSink[];
  botIds?: string[];
  allowInAutomation?: boolean;
}

export interface VaultAuditEntry {
  id: string;
  time: string;
  action: 'save' | 'update' | 'delete' | 'use' | 'denied' | 'reveal';
  itemId: string;
  itemTitle: string;
  fields: string[];
  botId?: string;
  runId?: string;
  sink?: VaultSink;
  /** 目标摘要（脱敏后的工具/窗口/域名/命令），绝不含明文 */
  target?: string;
  decision?: 'auto' | 'user-once' | 'user-run' | 'denied';
}
```

### 3.3 磁盘存储格式（`electron/core/vault/vault-store.ts`）

存储路径：`join(dataDir, 'vault.json')`，使用现有 `atomicJson`（文件权限 `0o600`）原子写入。

```ts
interface StoredVaultItem extends Omit<VaultItemMeta, 'unreadable'> {
  /** secretCodec.encrypt(JSON.stringify(Record<string, string>)) 产出的 base64 密文 */
  encryptedFields: string;
}

interface StoredVaultFile {
  version: 1;
  items: StoredVaultItem[];
  /** 环形保留最近 500 条审计记录 */
  audit: VaultAuditEntry[];
}
```

**存储与备份集成细节**：
- **加密**：直接复用 `electron/main.ts` 的 `secretCodec`（`Electron safeStorage`：macOS Keychain / Windows DPAPI / Linux Secret Service）。如果 `safeStorage.isEncryptionAvailable()` 为 `false`，写入抛 `AppError('vault.encryption_unavailable', '系统加密存储不可用，无法保存保险库条目')`，**绝不降级为明文存储**。
- **跨机备份**：扩展 `electron/core/backup/backup-secrets.ts`：
  - `Locate` 联合类型新增 `'vault.json'`；
  - `visitAll` 遍历 `vault.json` 的 `items[*].encryptedFields`，参与 `collectSecrets` / `rewrapSecrets` / `sealSecrets`。
  - `backup-rules.ts` 中 `vault.json` 符合 `APP_NAME` 且不在 `LOCAL` / `DERIVED_TOP`，自动纳入 `.aelionbackup` 备份；`bot-file.ts`（单个 Bot 导出）完全不涉及 `vault.json`。
- **Snapshot 隔离**：`electron/main.ts` 的 `snapshot()` **仅可**附带 `vaultCount?: number` 或 `vaultAvailable: boolean`（甚至完全按需 IPC 读取），**绝不**把 `StoredVaultItem` 放入 `state.sqlite` 或渲染进程 `Snapshot`。

### 3.4 稳定错误码（`AppError`）

测试全部断言 `errorCode(error)`，不断言中文文案：

| Error Code | 触发场景 |
| --- | --- |
| `vault.encryption_unavailable` | `safeStorage` 不可用时尝试写入 |
| `vault.not_found` | 引用的 `itemId`/`slug` 不存在 |
| `vault.field_not_found` | 条目存在但字段不存在 |
| `vault.ref_invalid` | 占位符格式非法或包含保留原型键 |
| `vault.unreadable` | 跨机未解密导致当前机器无法读取该条目密文 |
| `vault.sink_not_allowed` | 目标工具通道不允许使用该类别或字段（如把 `card` 传入 `exec_command`、把任意引用传入 `file_write`/`memory`/`group_send_message`） |
| `vault.bot_not_allowed` | 当前 Bot 不在该条目的 `botIds` 授权列表中 |
| `vault.context_not_allowed` | 在不允许的运行上下文中调用（如 headless/scheduled/group 使用 `card` 或未开放自动化的条目） |
| `vault.totp_invalid` | `totpSecret` 非有效 Base32 密钥 |
| `vault.denied` | 用户在审批卡片中拒绝本次使用（`InteractionDenied` 实例，`code = 'vault.denied'`） |

### 3.5 安全掩码预览规则（`maskPreview`）

- `email`：保留首字符与域名，如 `z***@example.com`（本地部分 ≤ 2 字符时 `***@example.com`）
- `phone`：保留后 4 位，如 `***-****-5678`
- `card_number`：去空格/连字符后仅保留后 4 位，如 `•••• 4242`
- `password` / `cvv` / `totp` / `apiKey` / `apiSecret` / `passphrase`：统一 `••••••`（不暴露长度）
- `multiline_key`（SSH 私钥）：展示密钥类型与公钥/内容 SHA-256 短指纹，如 `SSH Key (SHA256:9f3a…c1)`
- `text`（姓名/地址/用户名等）：长度 ≤ 4 全部 `••••`；> 4 仅保留前 2 字 + `***`（绝不展示完整地址或完整姓名，防止从目录拼出原始值）

## 四、引用语法与执行边界盲注（Blind Injection）

### 4.1 占位符语法（`shared/vault-refs.ts`）

```text
{{vault:<itemIdOrSlug>.<fieldKey>}}
```

- 匹配正则：`VAULT_REF_RE = /\{\{vault:([a-z0-9][a-z0-9_-]{0,63})\.([a-zA-Z][a-zA-Z0-9_-]{0,47})\}\}/g`
- 优先匹配 `item.id`，其次匹配 `item.slug`。
- **动态 TOTP 支持（`electron/core/vault/vault-totp.ts`）**：
  - 当条目包含 `totpSecret` 字段时，目录自动暴露虚拟字段 `totp`（`derived: true`）。
  - 解析 `{{vault:github.totp}}` 时，主进程用 `node:crypto` 的 `createHmac('sha1', base32Decode(secret))` 实时按 RFC 6238（30s 步长、6 位）计算当前一次性验证码（零外部依赖）。
- **严格失败策略**：在允许解析的通道中，如果检测到任何匹配 `{{vault:...}}` 的片段但对应条目或字段不存在，**立即抛出 `vault.not_found` / `vault.field_not_found`**，绝不静默把 `{{vault:...}}` 当字面字符串输到网站表单里。

### 4.2 通道能力矩阵与精确盲注实现

**核心架构铁律**：`harness.ts` 里的 `displayInput`、`describeTool`、`ExecutionLedger.begin`、`tool.intent` 日志、`toolDiff`、`HostApprovals` 审批界面与审批模型看到的永远是**未展开的含 `{{vault:...}}` 的原始参数**；解密展开只发生在**各执行器贴近操作系统/子进程/MCP 传输的最后一跳**。

| 工具 | 对应 `VaultSink` | 解析位置与注入机制 | 安全加固 |
| --- | --- | --- | --- |
| `computer`（VM 桌面） | `vm_desktop` | `electron/core/vm/computer.ts` 的 `perform()` 中，针对 `action === 'type'`（含 `batch` 内的 `type`）解析 `input.text` | 1. 改写 `computer.ts:358-364`：当含保险库引用时，不把明文/base64 拼进 `xdotool/xclip` 命令行参数（防 `/proc/cmdline` 和错误日志泄露），改为经 `vm.executeDesktop` stdin 管道写入 `xclip -selection clipboard -in`；<br>2. 发送 `CTRL+V` / `CTRL+SHIFT+V` 并等待 120ms 后，**在 `finally` 中立即执行 `xclip -selection clipboard -in </dev/null && xclip -selection primary -in </dev/null` 清空剪贴板**；<br>3. `open_app(url)` **禁止**包含 `{{vault:...}}`（防止凭据进浏览器 URL 历史）。 |

### 4.3 VM 侧环境变量与临时文件传输细节

`electron/core/vm/vm.ts` 的 `execute()` / `openTerminal()` 与 `vm-python.ts` 当前以命令行方式在 VM 内启动进程。为了保证 `vaultEnv` 与 `vaultFiles` **不经过 VM 内 shell 命令行参数（避免 `ps` 与日志泄露）**：

## 五、双路径存入与会话明文洗脱

### 5.1 路径 A：安全录入卡片（`vault_request`，零明文进入模型）

当 Bot 需要用户提供尚未存入的高敏信息（密码、支付卡、SSH 私钥、API Key 等）时，调用 `vault_request` 工具，而不是在文字里向用户索要明文。

1. **交互模型扩展**：在 `shared/types/core.ts` 的 `InteractionRequest` 联合类型中新增：
   ```ts
   | {
       id: string;
       botId: string;
       runId: string;
       createdAt: string;
       kind: 'vault_input';
       phase: 'waiting';
       title: string;
       reason: string;
       category: VaultCategory;
       /** 预填的建议 slug、绑定域名与需要用户填写的字段清单 */
       suggestedSlug?: string;
       bindings?: VaultBinding[];
       fields: Array<{ key: string; label: string; kind: VaultFieldKind; required?: boolean; placeholder?: string }>;
       /** 若传入 existingItemId，表示向已有条目补充/更新字段 */
       existingItemId?: string;
     }
   ```
2. **数据流**：
   - `Interactions.requestVaultInput(...)` 入队后，聊天区渲染 `VaultInputCard`（桌面和手机 PWA 均支持，遵循 `InteractionPrompts.tsx` 卡片样式）。
   - 卡片内密码/卡号/CVV 默认使用掩码输入，SSH 私钥支持多行文本或点击“从本地文件导入”（仅桌面端直接读文件，不经过聊天附件）。
   - 用户点击“加密保存并继续”后，渲染进程调用 `respondInteraction({ id, action: 'submit', vaultInput })`：
     - 主进程在 `Interactions` handler 中直接调用 `vaultService.save(vaultInput)` 落盘加密；
     - **内存中的 `vaultInput` 立刻丢弃**，绝不写入 `ChatMessage`、`WireMessage`、`events.jsonl` 或 `InteractionRequest` 历史；
     - `vault_request` 工具仅向模型返回脱敏元数据：
       `{ saved: true, item: VaultItemMeta, hint: "可使用 {{vault:<slug>.<field>}} 引用，模型不可见明文。" }`
   - 如果用户点击“取消”，`vault_request` 返回 `{ saved: false, cancelled: true }`（不中断整轮任务，让 Bot 询问是否改用 `request_user_control` 或跳过）。

### 5.2 路径 B：自然对话存入与即时洗脱（`vault_save` + `VaultScrubber`）

用户经常会直接说：“我的常用邮箱是 alice@example.com，收货地址是……，帮我存进保险库”，或者直接把一段 API Key / SSH Key / 账号密码粘贴在对话框里让 Bot 保存。

为了做到**“存入之后，当前 Bot 后续轮次和所有其他 Bot 都看不到明文，且历史与长期记忆不留痕”**，`vault_save` 必须走以下严格洗脱管线（`electron/core/vault/vault-scrubber.ts`）：

1. **前置屏蔽（执行前，`harness.ts:1762-1785`）**：
   - 当 `call.function.name === 'vault_save'` 时，在创建 `display` 气泡、调用 `ledger.begin(...)`、写入 `store.journal('tool.intent', ...)` **之前**，把 `displayInput.fields` 的值全部替换为 `"[已加密保存]"`，避免明文进入 `events.jsonl`、`ExecutionLedger` 和 UI 活动条。
2. **加密落盘**：
   - `vault_save` Handler 验证输入后调用 `vaultService.save(...)`，返回 `{ saved: true, item: VaultItemMeta, __scrubValues?: string[] }`（`__scrubValues` 为内部字段，由 Harness 消费后立刻 `delete`，绝不返回给模型）。
3. **后置洗脱（`VaultScrubber.scrubAfterSave`）**：
   - **清洗 assistant 的 `tool_calls` 记录**：在当前 `history`（`conversations[key]` / `groupContexts[key]`）和 `preparedContexts.get(run.id)` 中，定位本次 `vault_save` 的 `ToolCall`，将其 `function.arguments` 中的 `fields` 明文值替换为 `"[vault:saved]"`。
   - **清洗触发本轮的用户消息**：在当前 `run` 对应的 `user` 消息（含 `store.data.messages`、同轮 `history` 中对应 `WireMessage`、以及 `turnContext` 锚点副本）中，查找刚保存进保险库的明文字段值（长度 ≥ 4；对多行 SSH 私钥同时匹配去除首尾空白的完整块），替换为 `[保险库：${item.title}.${fieldKey}]`；在对应 `ChatMessage` 上标记 `vaultScrubbed: true`（前端可展示轻提示“已转存保险库并从对话中隐藏”），并调用 `store.touch(message)`。
   - **登记全局红名单**：立即将本次明文注册进 `vaultService.registerActiveSecrets(...)`，确保随后运行的 `MemoryCapture`（长期记忆提取）、`summaries`（上下文压缩）、`history_search`、`Diagnostics` 全程不可见明文。
   - **引导下一轮**：`vault_save` 返回值只包含 `VaultItemMeta`（含 `slug` 和各字段 `preview`），不回显任何传入明文。

## 六、权限、审批与多场景边界

### 6.1 使用确认交互卡（`kind: 'vault_use'`）

在 `shared/types/core.ts` 的 `InteractionRequest` 联合类型中新增：

```ts
| {
    id: string;
    botId: string;
    runId: string;
    createdAt: string;
    kind: 'vault_use';
    phase: 'waiting';
    itemId: string;
    itemTitle: string;
    category: VaultCategory;
    fields: string[];
    sink: VaultSink;
    /** 人类可读的注入目标说明，如 "工作电脑桌面输入" / "本机窗口：Google Chrome - Sign in to GitHub" / "执行命令：git clone …" / "MCP：github / create_issue" */
    targetSummary: string;
    /** 若条目配置了 bindings 且与当前检测到的目标不一致，设为 true 并在卡片高亮警告 */
    bindingMismatch?: boolean;
    expectedBindings?: VaultBinding[];
    /** 是否允许勾选“本任务内不再询问此条目”；card 类别可配置默认 false */
    allowRunGrant: boolean;
  }
```

- **确认方式**：复用 `Interactions` 队列，与 `computer_use` 同等地位——**仅允许人类通过桌面端、已配对手机 PWA 或连接器所有者操作放行，自动审核模型（`HostApprovals`）不参与且不可绕过**。
- **用户动作**：
  - `deny`：拒绝本次使用，抛 `InteractionDenied`（`code: 'vault.denied'`），遵守 AelionBot 既有拒绝语义（不自动重试、不绕过）。
  - `allow`：仅允许这一次工具调用。
  - `allow-run`：仅在当前 `runId` 内存态授予 `(runId, itemId, sink)` 临时通行（仅当 `allowRunGrant === true` 时提供；任务结束即销毁，不落盘）。

## 七、防泄漏脱敏体系与视觉侧信道

### 7.1 `VaultRedactor` 全链路文本脱敏

新增 `electron/core/vault/vault-redactor.ts`，职责如下：

1. **活跃红名单（`activeSecrets`）维护**：
   - 不在启动时把整个保险库全部解密常驻内存；
   - 只要某条目在当前进程内被 **解析盲注**、**`vault_save` 存入**、或 **触发诊断导出/记忆捕获**，其所有非空明文即登记到进程内存的 `activeSecrets` 索引（并在条目删除/修改时更新，支持按长度分类）：
     - **常规值（长度 ≥ 6）**：派生匹配集合 = `[raw, raw.trim(), encodeURIComponent(raw), JSON.stringify(raw).slice(1, -1), Buffer.from(raw).toString('base64')]`；若为 `card_number`，额外派生纯数字形式、每 4 位空格与连字符形式；若为 `multiline_key`，额外派生按行切分后每段 ≥ 16 字符的密钥体片段。按长度降序精确替换，替换为 `[redacted:vault]`。
     - **短值（长度 3–5，如 CVV / 4 位 PIN）**：**绝不**做无条件全局子串替换（否则会破坏输出里的正常端口号、行数、状态码）。仅在“本 `runId` 实际注入过该短值”时，对本次调用返回的结构化控件值（如 `host_computer` 的 `includeText` 中 `value="..."`）及紧邻 `cvv|cvc|pin|code` 语境做定向擦除；同时通过通道矩阵禁止 `card` 进入 shell/python/mcp，从源头杜绝短值回显。
2. **统一拦截出口（零遗漏）**：
   - **`Harness.executeTool` & `Harness.invokeNested` 返回前（含 catch 里的 error message）**：对返回值做递归字符串脱敏，**必须发生在**写入 `results/*.json`、`ExecutionLedger.finish`、`display.content`、`history.push`、`preparedContexts.push` 之前！
   - **`TerminalSessions.read`**：Host 与 VM 终端统一调用 `redactOutput`（补齐当前 VM 终端与无 Host 实例时的脱敏缺口）。
   - **`HostDesktop.observe`**：`includeText=true` 生成的控件文本强制经 `VaultRedactor` 脱敏。
   - **接入现有全部 `secrets()` 回调（`electron/main.ts`）**：
     - `HostComputer.options.secrets`
     - `MemoryCapture` / `Cognition` / `MemoryAdmin` 的 `secrets`
     - `Diagnostics.secrets`
     - `HostApprovals` 的 reviewer redactor

### 7.2 Computer Use 截图视觉侧信道分析与缓解

必须坦诚识别视觉侧信道的物理边界：如果目标网页使用 `<input type="text">`（非 `type="password"`）明文展示银行卡号、邮箱或地址，当 `computer` / `host_computer` 随后截屏并返回给多模态模型时，纯文本脱敏无法抹除图像像素里的文字。

设计采用**三层缓解策略**：

1. **原子批处理提交（Phase 1 必做）**：
   - 在系统提示词中明确规定：输入密码、卡号、CVV 或高敏字段时，必须优先使用 `computer(action="batch")` / `host_computer(action="batch")`，将“点击输入框 → 粘贴/填入 `{{vault:...}}` → 按 Enter 或点击提交按钮”合并为一次调用，只在提交/跳转后截取最终结果图；**严禁点击网页上的“显示密码”图标**。
2. **剪贴板与控件树防护（Phase 1 必做）**：
   - VM 桌面 `type` 粘贴含保险库引用文本后，立刻清空 `CLIPBOARD` 与 `PRIMARY` 剪贴板；
   - `host_computer` 优先使用 `set_value`，并在 `includeText` 返回前强制脱敏控件值。
3. **本机控件矩形截图自动遮罩（Phase 2 增强）**：
   - 在 `host_computer` 中，`DesktopCapture` 已知每个 `element` 的精确坐标矩形；若本次动作包含对 `element` 的敏感 `set_value` 且未发生窗口切换/提交跳转，可在保存给模型的截图副本上对该 `element` 矩形区域绘制实心遮罩（不修改真实屏幕，仅遮蔽发送给模型的 PNG）。

## 八、Bot 工具与系统提示设计（兼容 Prompt Cache）

### 8.1 新增工具定义（`electron/core/agent/tools/definitions/vault.ts`）

   - 参数：`{ query?: string, category?: VaultCategory, domain?: string, limit?: integer(1..50) }`
2. **`vault_save`**
   - 用途：将用户在当前对话中明确告知的个人信息、登录凭据、地址、支付信息、SSH 密钥或 API Key 存入或更新到保险库，供之后所有 Bot 盲注调用。存入后敏感明文会从后续上下文中自动隐藏。若用户尚未提供高敏信息（如密码、银行卡、私钥），请使用 `vault_request` 而不是在聊天中索要明文。
   - 参数：`{ id?: string, slug?: string, category: VaultCategory, title: string, notes?: string, tags?: string[], bindings?: Array<{ kind, value }>, fields: Record<string, string>, policy?: VaultAccessPolicy }`
   - 必填：`['category', 'title', 'fields']`
3. **`vault_request`**
   - 用途：在聊天中向用户弹出安全加密录入卡，请用户直接填写密码、银行卡、SSH 私钥、API Key 等敏感信息。用户填写的内容会直接加密存入保险库，不会出现在聊天记录或模型上下文中。仅在交互式会话可用。
   - 参数：`{ title: string, reason: string, category: VaultCategory, suggestedSlug?: string, bindings?: Array<{ kind, value }>, existingItemId?: string, fields: Array<{ key, label, kind?, required?, placeholder? }> }`
   - 必填：`['title', 'reason', 'category', 'fields']`

### 8.2 工具加载策略（`electron/core/agent/tool-loading.ts`）

- 将 `'vault_list'`, `'vault_save'`, `'vault_request'` 加入 `CORE_ACTIVE_TOOLS`。
- 在 `Harness.availableTools()` 中：
  - 仅当 `this.vault` 已装配时提供 `vault_list` / `vault_save`；
  - `vault_request` 额外要求 `Boolean(this.interactions) && !headless && !groupOrigin && !privateSession`。
- `COMPACT_TOOLS`（`< 32000` 上下文小模型）保留轻量的 `vault_list`，其余可通过 `tool_search` 按需激活。

### 8.3 系统提示词与轮次目录注入

1. **固定规则段（`electron/core/agent/prompts/system.ts`）**：
   - `HarnessPromptOptions` 新增 `vault?: boolean`。
   - 新增 `VAULT` 常量段（英文，与 `system.ts` 保持一致，精炼稳定，维护 Prompt Cache 稳定性）：
     - 说明用户保险库跨所有 Bot 共享，模型永不可见明文，也禁止试图打印、读取、回显、复制或通过脚本/截图套取明文；
     - 在需要输入凭据或个人资料时，先检查上下文中的保险库目录或调用 `vault_list`，再在 `computer`、`host_computer`、`exec_command`（优先 `vaultEnv` / `vaultFiles`）、`python_execute`（`vaultEnv`）或 MCP 参数中传入 `{{vault:<slug>.<field>}}`（或 `{{vault:<slug>.totp}}` 获取动态验证码）；
