# 手机端方案（在手机上远程使用 AelionBot）

状态：已实现，三期一起完成（2026-11-14）。使用说明见 [INTEGRATIONS.md](../INTEGRATIONS.md#手机访问)，中继部署见 [relay/README.md](../../relay/README.md)。

已定（2026-11-14）：客户端做 PWA，不上应用商店；中继放进本仓库（`relay/`），用户可以自己部署。

实现与方案的出入：

- 官方实例分两台：中继 `relay.aelion.chat`（Caddy + coturn 只做 STUN），手机网页 `app.aelion.chat`（与其他站点共用的 nginx）。配对链接打开网页，链接里带中继地址（`PairingLink.u`）。自己部署的中继同时提供网页，桌面端“手机网页地址”留空时就用中继地址。
- iOS 从主屏幕打开的网页应用与 Safari 不共享存储，所以手机端自己扫码（jsQR，打开相机时才加载），也可以粘贴配对链接。
- 每台电脑的推送用各自的 VAPID 密钥，而一个 Service Worker 注册只能有一个订阅，所以每台电脑注册一个作用域 `/p/<房间>/` 的 Service Worker 专门收推送；通知点开时带上 `?c=<房间>` 切到对应电脑。
- 同网直连（第三期）：手机经加密通道发 WebRTC offer，电脑在隐藏窗口（`electron/windows/remote-direct.ts`）里应答；数据通道里传的还是同一套加密帧。切换时双方先在中继上发 `switch` 标记，接收方读到标记后才改读直连（`shared/remote/paths.ts`），帧序不乱。直连断开后手机经中继重新连接，10 分钟内不再尝试直连。
- 原生 App 不做。
- 实现位置：`shared/remote/`（加密、帧、协议、手机端连接）、`electron/core/remote/`（中继连接、会话、视图、推送、WebAuthn）、`relay/`、`mobile/`；桌面设置页 `src/settings/RemoteSettings.tsx`。

目标：在手机上像用 ChatGPT App 一样使用自己电脑上的 AelionBot：看到 Bot 和会话列表，流式看答复和工作过程，发文字、图片、文件和语音，随时停止，批准本机操作，任务做完或需要批准时收到推送。Bot 仍然在电脑上运行，手机只是遥控器。

## 一、为什么 IM 不够

| | IM 连接器（现状） | 手机端（本方案） |
| --- | --- | --- |
| 会话 | 一个 IM 私聊对应一个工作会话，看不到其他会话 | 全部 Bot、工作会话，与桌面同一份数据 |
| 答复 | 只发最终回复，平台限制无法流式 | 流式文字、工作过程、内联图表 |
| 审批 | 文字指令或卡片按钮，各平台不同 | 和桌面相同的审批卡片，支持推送直达 |
| 桌面发起的对话 | 不同步到 IM | 双向同步 |
| 文件、工作电脑 | 只能收附件 | 预览、下载产物，查看工作电脑画面 |
| 依赖 | 飞书/企微/微信账号与机器人配置 | 扫一次码 |

IM 连接器保留，适合团队和临时使用；手机端作为个人远程使用的主要方式。

## 二、总体架构

```
 手机（PWA，app.aelion.chat）          中继（relay.aelion.chat）            电脑上的 AelionBot（主进程）
┌───────────────────────┐ WSS 密文 ┌──────────────────────┐ WSS 密文常连 ┌────────────────────────────┐
│ 会话列表 / 聊天 / 审批  │ ───────▶ │ 按房间转发字节          │ ◀─────────── │ RemoteHub                  │
│ 设备私钥（不可导出）    │ ◀─────── │ 不解密、不存内容        │ ───────────▶ │  ├ 握手、设备表              │
│ Service Worker：推送    │          └──────────────────────┘              │  ├ RemoteSession：白名单 RPC │
└──────────▲────────────┘                                                │  ├ RemoteView：按会话的增量   │
           │ Web Push（RFC 8291 加密，只有电脑和手机能解）                    │  └ WebPush                   │
           └──── FCM / Apple / Mozilla 推送服务 ◀──────────────────────────── └────────────────────────────┘
```

三个部分：

1. **桌面端**（`electron/core/remote/`）：开关、配对、设备管理、加密、把手机的请求交给现有 IPC handler、给手机算增量、发推送。
2. **中继**（新目录 `relay/`）：一个 Node 服务，部署在 aelion.chat 的 VPS 上。电脑和手机都是主动向外连，所以不需要公网 IP、端口映射或同一个 Wi‑Fi。中继只转发密文。
3. **手机端**（新目录 `mobile/`）：React PWA，部署在 `app.aelion.chat`，添加到主屏幕后就是一个 App。复用 `shared/` 的类型、i18n、状态同步，以及 `src/chat` 里的消息渲染组件。

## 三、关键选择

### 3.1 网络：官方中继 + 端到端加密（推荐）

| 方案 | 体验 | 代价 |
| --- | --- | --- |
| **官方中继**（推荐） | 4G、外面的 Wi‑Fi 都能用，零配置 | 需要运营一个服务，承担流量；中继地址可改成自建 |
| 局域网直连 | 只能在家里用 | HTTPS 页面不能连 `ws://192.168.x.x`（混合内容、浏览器的本地网络限制），PWA 基本做不了 |
| Tailscale / Cloudflare Tunnel | 能用 | 要用户自己装和配置，不像 ChatGPT App |
| WebRTC 点对点 | 同网时延迟最低 | 主进程没有 WebRTC，打洞失败仍要中继；作为后期优化 |

中继是公共服务，所以必须端到端加密，中继拿不到任何内容（见第四节）。设置里允许改中继地址，并提供自建脚本，给不想经过 aelion.chat 的用户。

### 3.2 客户端：PWA（已定）

- **PWA**：不用上架、不用 Apple 开发者账号，发布即更新；React、TypeScript 和现有组件都能直接用。iOS 16.4 起，添加到主屏幕的 Web App 支持推送，主屏幕 App 的存储也不受 Safari 7 天清理的限制。拍照、选文件用 `<input type=file>`，语音用 `MediaRecorder`。
- PWA 的限制：iOS 通知不能带按钮（不能在锁屏直接批准，要点进 App）；不能接收系统分享。
- **不做原生 App**：上架 App Store 成本高。以后真要做，可以用 Capacitor 把同一份 PWA 打包，代码基本不变。

### 3.3 推送：电脑直接发 Web Push

手机订阅推送时得到一个推送地址（FCM、Apple 或 Mozilla 的服务器）和加密公钥，通过加密通道交给电脑保存。电脑用自己的 VAPID 密钥签名，按 RFC 8291 加密后直接发给推送服务。中继不参与，aelion.chat 也看不到通知内容。实现用 `node:crypto` 自己写（约 150 行，和企微、微信协议一样不引入 SDK），或用 MIT 的 `web-push` 包。

推送时机（可以在手机上逐项关闭）：

- 需要批准或回答提问：总是推。
- 任务完成、失败：手机不在前台看这个会话，并且电脑最近 2 分钟没有键鼠操作（`powerMonitor.getSystemIdleTime()`）时才推，避免人在电脑前时手机也响。
- 自动化运行结果：按自动化的设置。
- 通知内容默认只有“Bot 名 + 完成/需要批准”，可选显示回复摘要。

## 四、安全

手机端能让 Bot 在电脑上执行命令，安全要求按“远程控制这台电脑”来设计。

### 4.1 配对

1. 设置 → 手机访问 → 添加手机，电脑显示二维码（用已有的 `uqr`）。二维码是 `https://app.aelion.chat/pair#…`，`#` 后面的内容浏览器不会发给服务器，包括：中继地址、房间号、电脑的公钥、一次性配对密钥（32 字节，5 分钟过期，用一次作废）。
2. 手机生成自己的密钥对（WebCrypto P-256，私钥不可导出，存在 IndexedDB），连上中继，握手时用配对密钥证明自己扫过码。
3. 电脑弹出“iPhone 请求配对”，点允许才生效。防止二维码在截图、录屏、共享屏幕时泄露。
4. 之后每次连接都用双方的长期公钥做双向认证，不再需要配对密钥。

### 4.2 加密通道

- 仿 Noise IK 模式：P-256 ECDH + HKDF-SHA256 + AES-256-GCM，每次连接用临时密钥（前向保密），帧带递增序号防重放。
- 加密代码放 `shared/remote/crypto.ts`，只用 WebCrypto：Node 24 和浏览器都有 `globalThis.crypto.subtle`，电脑和手机跑同一份代码，测试也只写一份。不用 X25519，因为 Safari 和旧版 Chrome 的 WebCrypto 不完全支持。
- 测试覆盖：握手、篡改、重放、错误公钥、过期配对密钥。

### 4.3 中继能看到什么

能看到：房间号（电脑公钥的哈希，不关联账号）、双方 IP、连接时间和流量大小。看不到：消息、文件、审批、Bot 名称、设备名。中继不记录载荷，只统计连接数和流量。

中继的防滥用：电脑注册房间要用私钥签中继给的随机数，别人占不了房间；每个房间同时最多 5 个手机连接；单帧大小、每日流量设上限。

### 4.4 设备管理与远程权限上限

- 设置页列出已配对设备：名称、最后在线、推送开关、移除。移除立即断开并删除公钥。设备表存 `dataDir/remote-devices.json`，推送订阅等字段用现有的 safeStorage `SecretCodec` 加密。
- 手机能做的事由白名单决定，不在白名单里的方法返回 `remote.forbidden`（`AppError`）。手机上**不能**做：修改模型、API Key、MCP、连接器、技能；打开终端；把会话权限改成“完全放行”；导出数据。
- 手机上可以批准单次操作和回答提问。“总是允许”在手机上二次确认，并完整显示将保存的命令规则。
- 手机端可选“打开时需要 Face ID / 指纹”：配对时注册一个 WebAuthn 凭证，电脑在新连接或批准操作时要求手机给出验证。放在第二期。

### 4.5 信任根

PWA 的代码从 aelion.chat 加载。如果网站服务器被攻破，攻击者可以下发恶意脚本，使用手机里存的密钥。缓解措施：

- 网站部署流程已经限制为强制命令的部署账号；PWA 走同样的流程，并加严格 CSP、不加载第三方脚本。
- 电脑端的权限上限（4.4）不依赖手机端代码，被攻破的页面也改不了。
- 用户可以自己部署 PWA 和中继（都在本仓库里），信任根就是自己的服务器。

## 五、协议

### 5.1 中继层（明文信封，只有路由信息）

- 电脑：`wss://relay.aelion.chat/v1/desktop`。中继发随机数，电脑回公钥和签名，中继绑定房间 `room = base64url(sha256(公钥))`。手机的连接通过这一条 WebSocket 多路复用：`{conn, data}`，`data` 是密文。
- 手机：`wss://relay.aelion.chat/v1/client?room=…`。电脑不在线时，中继回 `offline` 并带上最后在线时间。
- 心跳 25 秒；断线后按退避重连；电脑睡眠唤醒、换网络时立即重连。

### 5.2 应用层（加密通道里的 JSON）

- 请求 `{id, method, params}` → 响应 `{id, result}` 或 `{id, error: {code}}`；事件 `{event, data}`。
- 握手后交换 `{protocol, appVersion, capabilities}`。手机端总是最新版，电脑可能是旧版，所以手机按 `capabilities` 隐藏电脑不支持的功能。电脑的协议版本太旧时提示“请更新电脑上的 AelionBot”。

**状态：不推整份 Snapshot。** 桌面的 `Snapshot` 包含所有消息（用户本机 `state.json` 有 160 MB），手机只拿：

| 视图 | 内容 | 更新方式 |
| --- | --- | --- |
| 列表视图（连上就订阅） | Bot（名称、头像、状态）、工作会话、每个会话的最后一条和未读、待处理的审批和提问、`liveWork`、工作电脑状态摘要 | 增量 |
| 会话视图（打开某个会话时订阅） | 最近 60 条消息及对应的 runs，往上翻再分页取；该会话的流式回复 | 增量；流式内容限制在每秒 4 次 |

增量直接复用现有代码：把 `electron/core/app/state-sync.ts` 的 `StateSync` 改成泛型（`build` 返回任意带 `messages`、`runs` 的视图），每个手机连接一个实例；手机端用 `shared/state-sync.ts` 的 `share()` 合并，和桌面渲染进程一样按引用比较。工具消息只发标签和摘要，详情点开时再用 `readToolResult` 取。

**方法：复用现有 IPC handler。** `main.ts` 的 `handle()` 在注册 `ipcMain.handle` 的同时把 handler 存进一张表，`RemoteSession` 只调用白名单里的方法，参数校验和业务逻辑只有一份。第一期白名单：

| 用途 | 方法 |
| --- | --- |
| 聊天 | `send`、`cancel`、`retractChat`、`resumeChat`、`readToolResult` |
| 审批 | `respondInteraction`、`stopLiveWork` |
| 会话 | `createWorkSession`、`updateWorkSession`（改名、归档）、`setHostPermissionMode`（只能选“每次询问”“自动”） |
| 语音 | `transcribeSpeech`、`synthesizeSpeech`（用电脑上配置的语音服务） |
| 附件 | 手机专用：`remote.upload`（分块上传，单个 25 MB，交给 `attachments.importFiles`），`remote.blob`（分块下载，图片可要缩略图，电脑用 `nativeImage` 缩小） |
| 视图 | 手机专用：`remote.subscribe`、`remote.history`、`remote.visibility`（手机前台在看哪个会话，用于推送判断） |

需要 `ctx.window` 的方法（选择文件夹、文件对话框、预览窗口）不进白名单。

## 六、桌面端改动

- `electron/core/remote/`
  - `remote-hub.ts`：开关、连接中继、重连、管理每个手机连接、关窗口后保持运行。
  - `remote-devices.ts`：配对流程、设备表、撤销。
  - `remote-session.ts`：一个手机连接：解密、白名单分发、订阅。
  - `remote-view.ts`：构建列表视图和会话视图。
  - `web-push.ts`、`remote-notify.ts`：VAPID、加密、推送时机和合并（同一会话 10 秒内多条合并成一条）。
- `shared/remote/`：`protocol.ts`（消息类型、白名单、版本）、`crypto.ts`（握手和帧加密）。
- `electron/ipc/register-remote.ts` 和 `shared/ipc.ts`：`remoteState`、`setRemoteEnabled`、`startRemotePairing`、`decideRemotePairing`、`updateRemoteDevice`、`removeRemoteDevice`。
- `main.ts`：`handle()` 记录 handler 表；`changed()`、`streamsChanged()` 同时通知 `RemoteHub`；“关闭窗口后保持运行”的条件加上“手机访问已开启”（现在只看 `connectors.keepRunning`，`main.ts:1234`）；托盘显示手机访问状态。
- 电脑睡眠时手机就连不上了。手机访问的选项里加“开启时阻止电脑睡眠”（`powerSaveBlocker.start('prevent-app-suspension')`，不影响关屏），默认开。手机上显示“电脑离线，最后在线 23:10”。
- 设置页新增“手机访问”：开关、二维码、设备列表、中继地址（高级）、阻止睡眠。
- 手机发出的消息带 `ChatMessage.remote = { deviceId }`，桌面上显示一个小的“来自手机”标记。
- 新文案同步 `en.ts` 和 `zh-TW.ts`。

## 七、手机端

技术：`mobile/` 目录，独立的 Vite 配置（和 `website/` 一样），构建时把 `mobile/` 加进 knip 的入口。Service Worker 缓存外壳、处理推送和通知点击（深链到对应会话或审批）。

复用：`shared/` 的类型、i18n 和状态同步；`src/chat` 的 `MessageMarkdown`、`MessageBlocks`（图表、表格、widget 沙箱在手机浏览器里同样能用）、`MessageCodeBlock`、`InteractionPrompts`。这些组件现在直接调用 `window.aelion`，第一期由手机端装一个 `window.aelion` 垫片，把白名单方法转到远程，其余方法抛 `remote.unsupported`，组件不用改。之后再逐步改成通过 context 注入。

界面按手机应用来做，不照搬桌面：每屏只留一个主要操作，次要功能收进长按菜单和弹层，用手机手势（边缘右滑返回、长按、下拉）。参考了 ChatGPT App（单色底、胶囊输入框、长按菜单）和 Grok Bot 手机端（Bot 列表首页、接管电脑后交还）。设计稿是可点击的原型，在本地 `.local/mobile-ui/`（不进仓库；第一版留在 `v1/`），用示例数据渲染真实的头像、Markdown 和内联图表组件。

- **首页**：大标题 AelionBot，下面是电脑在线状态（点开切换电脑和设置）。需要你批准的事放在最上面，可以直接点“允许”。下面每个 Bot 一行，第二行写它正在做什么或最后一句话。不用抽屉，也不在列表里展开会话树。
- **对话**：顶栏只有返回、标题（Bot 名 + 会话名）、更多。用户气泡用 Bot 颜色的浅色调，Bot 回复不加气泡。Bot 干活时只显示一行状态（头像动画 + “正在编辑 评审材料.pptx · 第 3 步”），点开看步骤；Bot 在用工作电脑时，右边有一个小画面，点开看大图。
- **输入框**：只有 +、文字框（带麦克风）；运行中多一个停止，有内容时多一个发送。权限模式不放在输入框旁边。
- **审批**：批准按钮在屏幕下方、拇指够得到的位置，暂时取代输入框。原因、目录和“以后都允许”收在“详情”里。
- **切换会话**：点标题弹出这个 Bot 的会话列表和“新会话”。
- **长按消息**：复制、朗读、引用回复、选择文字。回复下面不放图标。
- **附件**：面板占键盘的位置，第一格是相机，下面是所有照片、文件、电脑上的文件。
- **工作电脑**：只有画面和一个“接管”按钮；接管后画面描边，完成后“交还给研究助手”。
- **推送**：标题是 Bot 名，正文一句话说清要你做什么或做完了什么。
- **深色模式**跟随系统；电脑离线时首页标题下变灰，说明消息会在电脑上线后送达，进行中的 Bot 显示停在哪一步。
- 设置、首次连接沿用第一版。
- 字体用系统字体（iOS 上是苹方），不下载 webfont；正文 17px（iOS 默认正文字号）；可点区域不小于 44px；输入框字号不小于 16px（小于 16px 时 iOS 会自动放大页面）。

## 八、中继服务

- `relay/`：Node 24 + `ws`，单文件为主，约 300 行；systemd 服务；nginx 反代 `relay.aelion.chat` 的 WebSocket。部署沿用网站的强制命令方式。
- 容量：每台开启手机访问的电脑常驻一条空闲 WebSocket，小 VPS 撑几千个没有问题。主要成本是图片和文件的流量，靠单文件上限、缩略图和每日流量上限控制。
- 自建：提供 `relay/README.md` 和一键脚本，在设置里填自己的地址即可。
- 测试：`relay/tests` 覆盖房间注册签名、多路复用、上限、离线提示。

## 九、分期

**第一期：能用**

- 中继、加密、配对、设备管理。
- PWA：Bot 和会话列表、流式聊天、发文字和图片/文件、停止、审批和提问。
- Web Push：审批提醒、任务完成。
- 桌面：设置页、阻止睡眠、关窗口后保持运行。

**第二期：好用**

- 语音输入和朗读。
- 产物预览和下载（图片、PDF、Markdown、HTML），保存或分享到手机。
- 工作电脑画面（按需截图，打开时每 2 秒刷新）。
- 自动化列表：立即运行、暂停。
- 群聊查看和发言。
- WebAuthn 解锁和审批验证。
- 电脑离线时消息留在手机，上线后发送（手机端排队，可以撤回）。

**第三期**

- 同一网络下 WebRTC 直连。
- 手机上接管工作电脑（noVNC 已在依赖里）。

## 十、风险与未决

- **中继运营**：服务对所有用户开放后，aelion.chat 要承担流量和可用性。可以先只给自己用（中继地址默认空，手动填写），稳定后再默认开启。
- **信任根**：见 4.5。
- **版本兼容**：手机端总是最新，电脑端可能落后几个版本，协议要向后兼容至少两个小版本，靠 `capabilities` 判断。
- **iOS 限制**：必须添加到主屏幕才能收推送；通知不能带按钮；后台时连接会断，回到前台重连并补齐增量（`from` 对不上就重新取视图，和桌面 `readState` 一样）。
- **双端同时操作**：两边看到的是同一份数据，草稿不同步；两边同时发送时按到达顺序进入现有的聊天队列。
