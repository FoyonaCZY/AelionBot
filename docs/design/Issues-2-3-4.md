# Issues #2、#3、#4

本次针对 GitHub 反馈修复请求兼容性与恢复行为，并加入个人资料设置。诊断包只作为数据读取，没有运行包内内容或将聊天原文加入源码。

## #2 图片输入兼容性与错误详情

[Issue #2](https://github.com/FoyonaCZY/AelionBot/issues/2) 的截图显示，先前发送过图片，随后发送纯文字“你好”也失败。诊断记录确认，所选 Bot 使用 `mimo-v2.5-pro`，服务连续返回 `No endpoints found that support image input`；诊断摘要里的“未配置”实际指全局默认模型，不能代表该 Bot 没有配置模型。

- 从模型列表的图片能力元数据识别支持情况，不依赖模型名字猜测；允许在具体模型选择中设置自动识别、支持图片或仅文字。
- 当前任务确实需要的图片不会被静默丢弃。不支持时显示明确说明、模型设置入口以及可展开的错误详情，保留附件和原对话。
- 新任务只需要文字时，若服务明确拒绝历史图片，省略旧图片后重试一次；模型会收到“图片未发送、不能声称看过”的说明。短期缓存该能力失败，避免每一步重复失败请求。
- 原始历史和图片文件不变，更换模型后仍可恢复图片任务。被省略图片的请求不用于学习 tokenizer 校准或上下文用量锚点，避免污染容量估算。
- 诊断增加实际发送图片数量；摘要优先显示最近失败任务的 Bot 模型。

## #4 工具消息顺序与旧记录恢复

[Issue #4](https://github.com/FoyonaCZY/AelionBot/issues/4) 中第一次错误发生于群任务，在十九项工具操作之后出现，随后继续请求持续返回工具调用配对错误。源码复现发现：发布群聊进度时，自己的发言可能插到 `assistant.tool_calls` 与对应 `tool` 结果之间。

- 群聊进度在工具批次未完成时只保存为群消息；结果记录完毕后再加入模型历史。
- 协议层保证每批调用后紧跟对应结果，再放入期间到达的进度/聊天事件。健康历史保持原顺序，兼容多协议原生输出。
- 缺失结果明确标记为未知，不伪造成功、不重放操作。孤立或损坏的调用保留为参考资料。
- 旧异常历史修复前先保存本地备份。修复后失效的摘要位置和裁剪视图会重建，避免继续使用错误的历史索引。
- 成功请求的缓存基线允许刚返回、尚未执行的尾部调用，不给它们添加未知结果，保持增量传输条件正确。
- 诊断增加协议层历史修复数量。

## #3 自定义身份

[Issue #3](https://github.com/FoyonaCZY/AelionBot/issues/3) 希望设置称呼和工作背景。

- 设置新增“个人资料”，包含称呼、身份/职业、工作背景，可保存或清空。
- 用于 Bot 开场白、主会话、私聊和群聊的后续模型上下文；资料更新以参考快照更新方式传达，不为了修改称呼重写旧聊天。
- 明确要求在答复、进度和协作中使用设定称呼，避免“@用户”。清空资料会明确撤销旧的称呼和背景。
- 群聊界面与新的人类消息使用自定义称呼，历史 Bot 发言不会被误标为人类。
- 个人资料不是新的任务或操作许可，不改变权限模式；诊断包不包含这些资料。
