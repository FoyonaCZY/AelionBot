# 用量、权限审核与 Bot 模型配置

## 用量

设置中的「用量」按当前系统时区展示，支持最近 1/7/30/90 天、自定义日期，以及按小时、天、月分组。Provider、模型、请求用途可组合筛选，点击分布图可以继续筛选；趋势图支持悬停和键盘查看。

主进程从完整的 `modelUsage` 历史聚合结果，再通过 `usage:query` 返回统计值。不会只统计快照中的最近 100 次请求，也不会把完整历史或 API Key 传到图表。

四种协议归一化为可缺省的输入、输出、总量、缓存读取、缓存写入、推理 token。缓存属于输入的细分，推理属于输出的细分。Claude 输入合计普通输入、缓存读取和缓存写入；Gemini 输出合计候选与思考内容。流式累计值覆盖前值，部分更新保留已有细分。服务端返回的总量优先；无完整用量时不拿本地估算代替图表实际值。

新记录带 `usage.version=2`，缺失字段保持缺失。旧版把部分缺失缓存字段补成了 0，因此早期的零缓存记录无法可靠判断是否命中；命中率仅计算有可确认缓存信息的请求，并显示覆盖情况。该百分比按累计缓存读取 token / 对应累计输入 token 计算，不平均单次比例。

独立请求、重试及失败记录按各自记录 ID 统计；错误若返回了用量则计入，否则计为未返回完整用量。Provider 名称随新记录保存，删除 Provider 后仍能识别历史记录。默认的任务 token 预算行为保持原有设置，部分用量可按原有估算逻辑用于任务预算。

## 自动审批

规则先检查常规项目操作和已有授权。需要模型判断时只保留执行状态，不展示权限卡片或通知。模型明确允许则继续，明确拒绝则停止；无法判断、审核失败或超时才显示原有会话内确认请求。

审核期间禁止提前允许或保存「始终允许」规则。用户仍可取消任务或改变权限模式，过期审核结果不会继续执行。远程 MCP 等原本要求单独确认的操作保持原有边界。

## 推理强度与自定义模型

Bot 的 `reasoningEffort` 独立于模型选择，使用默认模型时也可分别设置。默认模型选择中的推理强度用于默认模型自身（包括默认审核模型）；改变它不会覆盖现有 Bot 的推理强度。新建 Bot 会使用创建表单中的值，清空表示使用模型服务默认值。

启动时将旧 Provider 推理强度迁移到当时使用该 Provider 的 Bot 和默认模型选择，再移除 Provider 字段。迁移前保存仅含 Provider ID 与旧推理值的备份，避免重复迁移覆盖用户之后的调整。

模型名和推理强度均可输入，也提供已有模型和常用推理值的选择建议。模型名不受 `/models` 返回列表限制；推理值不限制为固定枚举，去除首尾空格后传给对应的 Chat Completions / Responses 字段。运行中的 Bot 保留已有模型变更保护。
