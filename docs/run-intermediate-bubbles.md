# 运行中的中间输出改气泡

设计稿：`.local/design/run-intermediate-bubbles.html`（运行中 / 完成折叠 / 完成展开三种状态）。

**实现状态**：已实现运行中 transcript、完成后折叠/展开、中间气泡复用普通气泡样式、中间气泡不带头像、运行中工具和 thinking 行合计只保留最近 3 个、以及底部状态只保留当前动作标题。

## 1. 现状

- `shared/chat/activity.ts` 的 `runSteps()` 把一次 run 里的 reasoning、中间 assistant 文本（`kind: 'note'`）和工具调用按时间顺序收集成 `RunStep[]`。
- `src/chat/RunProcess.tsx` 把它们全部塞进一个折叠区：
  - 运行中只显示最后 `LIVE_TAIL = 3` 个步骤；
  - 完成后默认整段收起，只剩「已处理 X · N 个步骤」；
  - 展开后，中间文本用 `NoteStep` 渲染成时间线里的一行 Markdown，不是气泡。
- 结果：模型在工具之间说的话（“工程渲染好了，我在检查画面”）被当成步骤细节藏起来，只有最终回答是气泡。

## 2. 目标

1. **运行中**：中间 assistant 文本直接以气泡出现在对话里，不折叠，不截断。
2. **完成时**：最终回答成为气泡，中间输出和工具步骤一起收进「已处理 X · N 个步骤」。
3. **展开后**：中间输出仍然是气泡，和运行时看到的一致；顺序不变。
4. 不改变最终回答、工具详情、错误提示、停止/继续等现有行为。

## 3. 状态机

```text
运行中 ──(run completed，出现 final)──▶ 完成·折叠
   │                                        │
   │ 用户点「已处理…」                         │ 用户点「已处理…」
   ▼                                        ▼
运行中·全部可见                          完成·展开（气泡 + 工具行）
   │
   └──(failed / cancelled / interrupted)──▶ 结束·折叠（保留错误/停止提示）
```

- `runPresentation()` 只在 `status === 'completed'` 且最后一条有内容的 assistant 存在时给出 `final`；运行中 `final` 为 `undefined`，所以所有已提交的中间文本都会是 `note` 步骤。这个判断不用改。
- failed / cancelled / interrupted 没有 final，统一折叠；错误卡片或「已停止」提示继续显示在折叠条下方。

## 4. 视觉

### 4.1 运行中

按时间顺序直接铺开，不再有顶部的「正在处理 · N 个步骤」列表：

```text
[用户气泡]

⌘ 执行命令  maas ... --force        0.8s ✓
(D) 工程已经渲染完成，输出在 out.mp4。我在检查画面。
⌘ 执行命令  ffmpeg -v error ...    (spinner)
(D) 视频流解码没有报错，时长 3.17 秒。再确认音轨…
```

- 中间文本用和普通 assistant 消息相同的气泡（`--bubble` 背景，18px 圆角，14px 正文）。
- **中间气泡一律不带头像**，直接从左侧开始，和工具行左对齐。运行时头像在底部的 `BotWorkingStatus` 上，完成后在最终回答上，不重复出现。
- 工具步骤保持现在的紧凑行：图标、动作、参数摘要、耗时、状态。
- 步骤间距 8–10px，比普通消息的间距紧，避免一次 run 拉得过长。
- 底部的 `BotWorkingStatus` 只保留当前动作标题（“正在检查音轨”），头像和标题在卡片内上下居中；它负责“现在在做什么”，气泡负责“已经说了什么”。
- 不再显示“当前操作已持续 12 秒，尚未返回最终结果”这类时长说明；等待过久的提醒仍由现有的慢速提示承担。
- 不放行内“停止任务”按钮：运行中输入框右侧的发送键已经是停止键，不重复提供同一个操作。
- 运行中不再显示顶部的折叠条，避免和底部状态重复。

### 4.2 完成·折叠

```text
[用户气泡]
▦ 已处理 2 分 13 秒 · 6 个步骤  ›
(D) 成片在这份回复里：…  [附件]
```

- 折叠条替换原来的过程列表，位置在最终回答上方。
- 中间气泡全部隐藏，不保留占位。
- 折叠条本身仍是 12.5px 的弱化文字，不加底色。

### 4.3 完成·展开

- 折叠条展开后，下面按原顺序恢复完整 transcript：工具行 + 中间气泡 + reasoning 行。
- 气泡样式与运行时完全一致，避免“展开后变成另一种东西”。
- 展开区沿用现在的左侧细线（`border-left`），气泡放在线的右侧；不再给每个气泡加卡片边框。
- 最终回答始终在展开区之外、折叠条下方，不参与折叠。
- 用户主动展开时不做「还有 N 个」截断，全部显示。

## 5. 行为规则

| 场景 | 行为 |
| --- | --- |
| 模型流式输出中间文本 | 继续由 `StreamingReply` 显示草稿气泡；提交后变成 transcript 里的 note 气泡，位置不变，不重复渲染 |
| 中间文本是纯空白 / 只有 reaction | 不生成气泡（沿用 `runSteps` 的 `readableContent` 判断） |
| 中间文本带附件 | 气泡内显示附件列表，和普通消息一致 |
| reasoning | 保持紧凑的「已思考 N 秒 · 摘要」行；用户设置隐藏 reasoning 时整行不出现 |
| 工具和 thinking 很多 | 运行中气泡永不折叠；气泡以外的步骤只保留最近 3 个，较早的收进顶部一行「还有 N 个步骤」，点一下展开全部，展开后顶部换成「收起较早的步骤」 |
| 完成后的默认状态 | 折叠（和现在一致）；点折叠条展开 |
| 失败 / 取消 / 中断 | 折叠 transcript，保留错误卡片或「已停止」提示和「继续处理」按钮 |
| 搜索命中中间文本 | 沿用 `REVEAL_MESSAGE_EVENT`：自动展开该 run，再滚动到对应 `data-message-id` |
| 正在向上翻看时 run 完成 | 折叠不能让视口跳动；优先保持当前滚动锚点，用户在底部时保持在底部看最终回答 |
| 一条 run 里连续多条中间文本 | 每条一个气泡，都不带头像，从左侧开始 |
| 群聊 / Bot 私聊 | 先保持现状（群聊与 peer 的渲染路径独立），本次只改 Bot 主对话和工作会话 |
| 复制 / 引用 / 钉住 | 中间气泡只读，不提供操作按钮；这些操作仍然只针对最终回答 |

## 6. 实现拆分

1. **纯函数** `visibleRunSteps(steps, { running, expanded })`（放在 `shared/chat/activity.ts` 或新建 `run-transcript.ts`）：
   - 运行中：返回全部 `note`，工具和 reasoning 步骤合计保留最后 3 个，返回 `hiddenSteps` 数量；
   - 完成且折叠：返回空；
   - 完成且展开：返回全部。
   这样可以先写测试，再接 UI。

2. **`RunProcess` 重构**：
   - `running` 时不渲染折叠条，直接渲染 transcript；
   - `!running && !expanded` 只渲染折叠条；
   - `expanded` 渲染折叠条 + 完整 transcript。
   - 现有 memo 比较器需要把 `note` 的 `message.content` 变化纳入比较（现在按 message 引用比较，提交后是新对象，一般够用）。

3. **`NoteBubble` 组件**：
   - 复用 `Message` 的气泡样式，而不是 `NoteStep` 的裸 Markdown；
   - 不带头像，直接从左侧开始；
   - 支持 `mentions`、附件、Markdown；
   - 外层保留 `data-message-id`，供搜索定位；
   - 不渲染操作栏、状态、时间。

4. **CSS**：
   - 删除 `.run-step-note` 的裸文本样式，新增 `.run-note`（只有气泡，从左侧开始）；
   - transcript 容器在运行中无边框；展开时保留左侧细线；
   - 气泡在 transcript 内 `max-width: 100%`，避免二次 82% 缩窄；

5. **测试**：
   - `visibleRunSteps` 的三种状态和工具截断；
   - 连续 note、空白 note、reasoning 设置隐藏；
   - 现有 `runSteps` 测试保持不变。

## 7. 待定

1. 失败/取消时是否也折叠中间气泡？我倾向折叠，保持“结束后只剩结果和原因”的清爽；如果你希望失败时保留现场，可以只折叠工具行。
2. 是否需要“跳到最新”按钮？长任务运行中用户向上翻时可能有用，但会增加一个悬浮控件；第一版可以不做。
